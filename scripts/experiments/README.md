### Восстановление входа после G13

Повторная диагностика S16 установила конкретный отказ: Codex не может обновить вход, поскольку refresh token уже использован. Допустимый JSON и `codex login status` сами по себе не подтверждают живой доступ. Диагностика описана в `docs/experiments/s16/auth-recovery.json`.

Для IAM нужен отдельный вход. Не выполняйте `codex logout` в обычном домашнем каталоге Codex: это затронет текущую рабочую сессию. В доверенном терминале Mac:

```sh
umask 077
mkdir -m 700 -p "$HOME/.iam-secrets/codex-login"
CODEX_HOME="$HOME/.iam-secrets/codex-login" \
  codex -c 'cli_auth_credentials_store="file"' login
```

Завершите обычный вход в открывшемся браузере. В продолжении S16 вход по устройственному коду вернул ошибку страницы, а обычный браузерный вход прошёл. Проверка IAM требует, чтобы файл входа находился вне проекта и имел права `600`; токены нельзя присылать в чат.

Импортируйте вход в отдельный рабочий файл IAM. Имя `auth.json` запрещено для записи: в него может писать штатный `codex login`. Новый адаптер принимает служебные поля свежего CLI, оставляя в передаче только известные поля подписки и `last_refresh`. Команда сохраняет оригинал, ничего не выводит и отказывается перезаписывать старый импорт:

```sh
umask 077
PYTHONPATH=src .venv/bin/python - <<'PY'
import json, os, stat
from pathlib import Path
from iam.providers.codex.auth import normalize_auth, validate_auth_path
from iam.providers.codex.command import REPO_ROOT
source = Path.home() / '.iam-secrets/codex-login/auth.json'
validate_auth_path(str(source), REPO_ROOT)
fd = os.open(source, os.O_RDONLY | os.O_NOFOLLOW)
with os.fdopen(fd) as stream:
    clean = normalize_auth(json.load(stream), include_refresh=True)
target = Path.home() / '.iam-secrets/iam-managed.json'
assert stat.S_IMODE(target.parent.stat().st_mode) == 0o700
fd = os.open(target, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w') as stream:
    json.dump(clean, stream)
PY
```

С этого момента рабочим файлом владеет только IAM. Не запускайте исходный login одновременно с импортом и не редактируйте рабочий файл вручную во время сеанса. Для нового входа остановите IAM, используйте отдельный CODEX_HOME и новое имя импорта. Затем повторите живую проверку:

```sh
PYTHONPATH=src .venv/bin/python scripts/codex/verify.py \
  --auth-file "$HOME/.iam-secrets/iam-managed.json" \
  --output-dir "$HOME/.iam-evidence/s16-restored-check" --live --persist-auth-updates
```

`run_real.sh` включает сохранение обновлений автоматически. Launcher возвращает текущую авторизацию отдельным завершающим конвертом; адаптер исключает его до разбора ответа модели и атомарно сохраняет изменения с правами 600. Блокировка рядом с рабочим файлом допускает только одного IAM-исполнителя; чужие изменения проверяются перед записью. Она не координирует произвольные программы, которые игнорируют блокировку, поэтому рабочий файл нельзя разделять со сторонними писателями. Папки компьютера в Docker не монтируются.

Это реализует обычное сохранение обновлений по [инструкции OpenAI](https://learn.chatgpt.com/docs/auth/ci-cd-auth). При таймауте, убийстве процесса или повреждении завершающего конверта — техническая пауза; восстановление входа в этих случаях не гарантируется. По умолчанию CodexProvider и панель остаются в режиме чтения авторизации; доработка включена для S16 и явно выбранной проверки, а не для всех путей приложения.

Скрипт сначала проверяет изоляцию без вызова модели. Его каталог вывода должен быть абсолютным и вне проекта, поскольку проверочный отчёт изоляции хранится снаружи. Затем запускается только закреплённая GPT-6-Luna в существующей изоляции Docker. Нужны установленное окружение `.venv`, образ `iam-codex:1`, сеть и посредник из `docker/README.md`, внешний файл подписочного входа с правами 600. Секреты не выводятся и не копируются в репозиторий.

Каждый вложенный сеанс имеет предел 10 попыток исполнителя или 30 минут. Варианты ограничены четырьмя ключевыми решениями; исправление формата — не более одного раза со стороны ядра, внутренний повтор адаптера выключен. После ошибки входа/лимита/доступности дальнейшие внешние вызовы прекращаются. Вызовы исправления формата учитываются в бюджете. Скрытого перехода на другую модель нет.

Результаты: `matrix.csv` (ровно 48 ячеек), `runs.json`, `summary.json`, `checks.csv`, базы и трассы внутри каждой ячейки. Восемь сценариев содержат вложенные ветви, поэтому полная матрица даёт 72 отдельных прогона и 90 решений. Промежуточные таблицы записываются после каждой ячейки. Автоматического продолжения того же каталога пока нет: после устранения причины используйте новый каталог, сохранив предыдущий как свидетельство сбоя.

`blind/` содержит только фрагменты, для которых найден исходный текст без явных подсказок. Это предварительный материал, не готовые диалоги. Ключ — `private/key.json`, вне `blind/`; не открывайте его до оценки. Пакет может быть пустым. Подробности оценки — `docs/experiments/rubric.md`. Перед переносом живых трасс в Git их нужно проверить сканером по действительным значениям токенов; SQLite и файл входа в Git не включать.

### Продолжение S16: память и разговоры (D-029)

Прежний запуск без дополнительных параметров сохраняет исходные варианты. Для повторного сравнения с общим экспериментальным адаптером `conversation-v2`:

```sh
PYTHONPATH=src .venv/bin/python -m iam.experiments.report \
  --mode live --conversational --persist-auth-updates \
  --auth-file "$HOME/.iam-secrets/codex-s16-managed-20261030.json" \
  --output "$HOME/.iam-evidence/s16-conversation-new"
```

После окончания матрицы, последовательно с тем же рабочим импортом, запустите разговоры:

```sh
PYTHONPATH=src .venv/bin/python -m iam.experiments.report \
  --mode live --dialogues --persist-auth-updates \
  --auth-file "$HOME/.iam-secrets/codex-s16-managed-20261030.json" \
  --output "$HOME/.iam-evidence/s16-dialogues-new"
```

`--dialogues` включает адаптер автоматически. Два одинаковых разговора по шесть реплик человека × три варианта × два повтора дают 12 разговоров и 72 решения. У A/B вызывается выбранная GPT-6-Luna; C отвечает локальными цитатами. Это фиксированный сценарий человека, а не живой собеседник, реагирующий на ответ. Многоходовой стенд имеет отдельный явный предел шесть решений; исходная матрица сохраняет предел четыре. Бюджет каждого сеанса остаётся 10 попыток/30 минут, включая единственное исправление формата ядром. Ошибка провайдера останавливает дальнейшие внешние вызовы внутри серии.

Чтение происходит после выбранного внимания. Прямо заданное билетом продолжение занятия без чтения сохраняется. Высказывания записываются с источником и общей группой источника: повтор не становится независимым подтверждением истины. Модель может предложить точную цитату и исправление доступной прежней записи того же источника; ядро сохраняет старую версию и связь пересмотра. Истинность и смысл исправления свободного текста не доказываются. Обычное извлечение исключает архив и заменённые записи. При `memory_off` прошлые реплики и память не отправляются модели.

Слепой пакет `--dialogues` включает только разговоры со всеми шестью подтверждёнными симулируемыми отправками и целой базой; модельные заглушки в него не входят. Неотправленный ответ не подменяется текстом предложения. Стиль C может раскрывать вариант. Ключ по-прежнему хранится в `private/key.json`, отдельно от публичного пакета; оценки пользователя остаются пустыми. Обычный пакет основной матрицы по-прежнему содержит предварительные фрагменты решений.

### Продолжение S16: собственное занятие (D-030)

```sh
PYTHONPATH=src .venv/bin/python -m iam.experiments.report \
  --life --mode live --persist-auth-updates \
  --auth-file "$HOME/.iam-secrets/codex-s16-managed-20261030.json" \
  --output "$HOME/.iam-evidence/s16-life-new"
```

`--life` — отдельный life-v1 эксперимент после обратной связи о подмене личности помощником. Он не меняет восемь исходных билетов и прежние разговоры. Десять возможностей выбора включают занятия до уведомления, два сообщения человека и продолжение после остановки/нового старта той же временной биографии. Между сеансами проходят календарные сутки; время жизни в остановке не идёт. Это один процесс стенда, не восстановление после перезапуска программы.

A выбирает следующее действие моделью. B/C выбирают одним явным правилом; B обращается к модели только за текстом уже выбранной реплики, C использует местный шаблон. Все три работают в одном конечном мире: авторская миниатюра и лабораторная последовательность по три части. Следующая часть открывается только подтверждённым действием работы. Мир не оценивает понимание текста, человеческие эмоции или качество исследовательского вывода. Интерес растёт фиксированной формулой после продвижения: это проверяемый параметр кандидата, не доказательство переживания.

Чтение уведомления — отдельное действие, после него можно не отвечать. Возможны работа, отдых, отсутствие действия и сообщение. Инициатива без текущей реплики требует подтверждённого собственного опыта и ссылки на него; без нового прочитанного сообщения человека допускается одно самостоятельное обращение. Произвольный текст реплики не проверяется на психологическое давление; инструкция просит его не создавать. В `memory_off` исключены записи, рабочая история и выученные интересы; текущая прочитанная реплика остаётся до следующего выполненного действия. Видимое физическое состояние занятия (номер открытой части), энергия и техническая защита повторов сохраняются. В `motivation_off` скрываются мотивы, выученные интересы и бонус продолжения дела; доступные действия сохраняются. A получает список оценок, но свободна от правила максимума B/C.

Матрица: три адаптера × три условия (`full`, `memory_off`, `motivation_off`) × два повтора = 18 временных биографий / 180 возможностей выбора. Бюджет каждой биографии: 16 внешних попыток / 30 минут; единственное исправление формата ведёт общий цикл. Другой модели или платного API нет. Запуски с одним файлом входа должны идти последовательно.

В `blind/` входят полные десятишаговые биографии основного условия, прошедшие целостность и выполнение всех решений. Обязательного количества реплик нет: молчание и занятия сохраняются на своих местах. Заглушки A/B не включаются. `private/key.json` остаётся снаружи Git; поля оценок пусты. Реплики и результаты не переписываются для улучшения впечатления. Стиль может раскрывать источник. Эпизоды не доказывают готовую личность и не закрывают G03.

### S16 D-031: развитие биографии, интересов и отношений

```sh
PYTHONPATH=src .venv/bin/python -m iam.experiments.report \
  --development --mode live --repeats 2 --persist-auth-updates \
  --auth-file "$HOME/.iam-secrets/codex-s16-managed-20261030.json" \
  --output "$HOME/.iam-evidence/s16-development-new"
```

Новый каталог, внешняя авторизация с одним IAM-писателем, прежняя изоляция и выбранная GPT-6-Luna. `--development` несовместим с `--life`/`--dialogues`. По умолчанию два повтора; один разрешён для диагностики и не выдаётся за полную серию. 12 биографий × 18 возможностей выбора, плюс четыре одинаковых пробы по два выбора из одного сохранённого прошлого каждой биографии. Всего 60 экспериментальных баз / 312 возможностей выбора. Каждая биография содержит шесть отдельных открытий/закрытий хранилища; контрольные копии не сливаются обратно. Бюджет каждого сеанса — 10 попыток/30 минут, единственное исправление формата ведёт цикл; повторы провайдера отключены.

Собственные тексты действительно сохраняются в `artifacts/` до подтверждения записи. Версии и их источники индексируются в состоянии. Интересы/отношения не растут автоматически за действие; модельные интерпретации с точными цитатами проходят отдельные проверки. Повтор события или того же полного текста-основания не накапливает оценку одной темы/отношения. Архив и выключенные интерпретации не возвращаются в контекст. Тексты сообщений источника не становятся истиной сами по себе.

`assessment.json` различает структурные связи и отдельную смысловую проверку. Без последней `blind/` содержит пустую форму: прежний опыт показал, что формальный текст нельзя предъявлять как готовую личность. Смысловую проверку проводит разработчик по всей биографии; человеческие баллы не назначаются. Полная методика — docs/experiments/development/SPEC.md.

Проверка и безопасная публикация завершённой серии:

```sh
PYTHONPATH=src .venv/bin/python scripts/experiments/verify_development.py \
  "$HOME/.iam-evidence/s16-development-new" /новый/каталог/публикации \
  --auth-file "$HOME/.iam-secrets/codex-s16-managed-20261030.json"
```

Проверяются базы/хеши, общее прошлое ветвей, отсутствие скрытого чтения, источники/цитаты интерпретаций, диапазоны изменений и действительные файлы собственных работ. Ключи/SQLite/авторизация не публикуются. Файлы `biographies/` — диагностический материал, могут раскрывать вариант; их не следует смешивать со слепым пакетом.

Исправленный development-v2 сохраняет тот же полный режим по умолчанию. Для адресной повторной диагностики после найденного дефекта можно явно выбрать адаптеры, например `--development --variants A --repeats 1`. Это две биографии/10 баз, а не полная сравнительная серия. При частичном обновлении отношения остальные оси сохраняются; инициатива допускается с доступным собственным опытом/интересом и прежним ограничением повторов. Версии и исходные данные сохраняются раздельно.

`development-v3` добавляет отдельную ограниченную операцию appraise после подтверждённого результата. Её вызовы входят в общий бюджет 10 попыток/30 минут сеанса. Действия/сообщения из этой операции не принимаются; можно сохранить проверенную интерпретацию/намерение или оставить состояние без изменений. Нет автоматического роста интереса/близости. Исходный профиль/черты/мотивы явно передаются. При memory_off стадия отключена; C не получает модельного понимания. Для воспроизведения каждой исторической серии используйте сохранённую версию источников, не называйте данные v1/v2 результатом V3.

`development-v4` (D-032) отделяет подтверждённую свою операцию от содержания прочитанного/сочинённого. Для самомодели нужна полная цитата self_quote записи/открытия своего проекта и kind=autobiographical. Материал или сообщение человека не служат основанием такого биографического вывода. В контекст входят только доступные experience_sources с уже использованными основаниями, таблица appraisal_kinds и список available_actions. Критерии допуска и сценарий не меняются. Проверяющий скрипт сохраняет совместимость с историческими v1–v3 и отдельно проверяет новые собственные основания v4. Контроль и живой запуск храните в новых каталогах.
