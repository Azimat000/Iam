# Проверка изоляции Codex

После сборки образа и запуска посредника из `docker/README.md`:

```sh
PYTHONPATH=src .venv/bin/python scripts/codex/verify.py --output-dir "$HOME/.iam-evidence/codex"
```

Сценарий использует тот же `docker_run`, что и адаптер. Проверяет версию и архитектуру CLI, пользователя, запрет записи в корень, отсутствие дополнительных прав, посторонних монтирований и Docker socket, ограничения ресурсов, права временного файла входа и его удаление, пустое хранилище нового контейнера, внутреннюю сеть, разрешённое соединение через посредник, отказ постороннему адресу и отказ прямому выходу. Диагностика использует только искусственные данные входа и не обращается к модели.

Для одного запроса к модели укажите отдельный файл входа подписки после `codex login`:

```sh
chmod 600 "$HOME/.iam-secrets/codex-auth.json"
PYTHONPATH=src .venv/bin/python scripts/codex/verify.py \
  --auth-file "$HOME/.iam-secrets/codex-auth.json" \
  --output-dir "$HOME/.iam-evidence/codex-live" --live
```

Файл должен находиться вне репозитория, быть обычным файлом без символической ссылки и иметь права `600`. Сохраняйте только свой файл подписки с `auth_mode: "chatgpt"` и `tokens`; ключ API не подходит. Сценарий не выполняет вход, не выводит содержимое файла и не исправляет его права. Полный домашний каталог передавать не нужно.

Для повторных живых запросов S16 используйте отдельный рабочий импорт и флаг `--persist-auth-updates` вместе с `--live`: [подготовка входа](../experiments/README.md). В этом режиме имя `auth.json`, жёсткие ссылки и небезопасный каталог запрещены. Обновлённые штатным CLI токены и `last_refresh` сохраняются атомарно с правами 600; завершающий конверт не включается в ответ модели или журнал. Один импорт принадлежит только IAM и защищён общей блокировкой; сторонний login/ручная запись в него во время сеанса запрещены. При таймауте или отсутствии конверта — остановка с неопределённым состоянием входа. Без флага файл не меняется.

`--live` использует `CodexProvider`, строго `gpt-6-luna`, без повторной попытки: один короткий искусственный запрос с предложением `no_action`. При провале предварительных проверок запрос не отправляется. Инструменты в ответе считаются провалом. Ответ модели и сырые ошибки не попадают в отчёт.

Во внешнем каталоге создаётся `report.json`: только закреплённые имена проверок, `PASS`/`FAIL`/`UNVERIFIED`, версия CLI, модель и итог. Без `--live` доступ к модели отмечен `UNVERIFIED`; это не подтверждение работоспособности подписки. Любая отсутствующая обязательная проверка мешает положительному итогу. Код выхода: `0` — запрошенные проверки прошли, `1` — провал, `2` — небезопасные входные данные или невозможность записать отчёт. Сценарий не печатает сырые команды, stdin или stderr.
