# Проверка Telegram (барьер G02)

Код S09 проверен на поддельном HTTP-сервере. Настоящий Telegram отдельно проверяет оператор.
Нужен Python 3.13+, бот из BotFather и числовой Telegram ID оператора. Сначала откройте
личный диалог с ботом и нажмите Start. У бота не должно быть webhook и второго получателя
getUpdates: одновременно используйте только один процесс. Скрипт ничего не удаляет на сервере.

Токен не пишите в командную строку, файл проекта, чат или журнал. В zsh загрузите его скрытым вводом:

```zsh
read -rs 'TELEGRAM_BOT_TOKEN?Токен бота: '; export TELEGRAM_BOT_TOKEN
read 'TELEGRAM_USER_ID?Ваш числовой Telegram ID: '; export TELEGRAM_USER_ID
python3 scripts/telegram/verify.py --data-dir "$HOME/.local/share/iam/telegram-check" --polls 2
unset TELEGRAM_BOT_TOKEN TELEGRAM_USER_ID
```

Пока скрипт ждёт, отправьте боту два разных сообщения. Приём идёт в остановленном сеансе,
без вызова модели. Печатаются только количество, offset и время последнего успешного опроса.
Запустите ещё раз с теми же данными: сохранённые сообщения не должны добавиться повторно.
Сообщение с другого аккаунта и сообщение из группы не должны попасть в inbox. Содержимое
отвергнутых сообщений не сохраняется. Изменение прав обычным текстом не выполняется.

Чтобы проверить отправку, повторите команду с `--send-test`: скрипт создаст одно предложение
тестовой модели, проведёт его через ядро и отправит «Iam: проверка отправки Telegram.».
Это явная отправка в ваш личный диалог. Каждое новое выполнение с этим флагом отправляет
новое сообщение. `confirmed` значит, что Telegram вернул подтверждение; `unknown_outcome`
значит, что неизвестно, дошло ли сообщение. Автоматического повтора нет.

Данные проверки — отдельная экспериментальная личность `exp_…`, никогда не рабочая личность.
Не переносите её биографию в постоянное хранилище. Токен в базе не сохраняется; входящие тексты,
включая случайно присланный секрет, хранятся как исходное сообщение. Экспорт удаляет известные
секреты. Резервные копии содержат исходные данные: храните их как личную информацию.

Включённый Mac с запущенным приёмником необходим для получения сообщений. Telegram хранит
обновления **не дольше 24 часов**; после более долгого выключения часть входящих может быть потеряна.
Даже короткий простой не гарантирует доставку при других сбоях. S10 должен показывать давность
`Receiver.last_poll_at` и предупреждение о превышении 24 часов; перенести это в RUNBOOK в S27.

## Подключение к приложению в S10

Один `Store` и `StateController` принадлежат одному процессу; `Receiver`, `Sender` и цикл используют
их вместе. Приёмник работает также при paused/stopped; не открывайте второй Store-писатель.
`CreatorBridge.poll_replies()` опрашивает сеть и сам пишет inbox/события, возвращая пустой список:
Runner не должен заново записывать те же входящие. Длинный опрос в S10 нужно обслуживать так,
чтобы не блокировать панель; не передавать SQLite-соединение произвольным потокам.

`Sender.execute` подключается как исполнитель сообщений (`World`); для остальных возможностей
S10 нужен общий маршрутизатор. Поддерживаются только числовые получатели из белого списка.
Уведомления `notices(N1/N2)` скрывают текст; `read_content` выдаёт его только после `input.read`.
Полное решение внимания о чтении остаётся S20.

В общей схеме outbox `requested` соответствует pending, `unknown` — uncertain. `result_seq` остаётся
NULL: исход транспортного запроса и внешний message_id сохраняет Sender, а событие подтверждения
и память пишет существующий Cycle. После обрыва незавершённая попытка становится uncertain.
Одна попытка на action_id; один дополнительный повтор по умолчанию допустим только с новым
принятым действием, `retry_of` и явным `operator_approved=True`. Повторы повторов запрещены.
Не создавайте новый action_id для обхода этого механизма при восстановлении после сбоя.

Позиция опроса, ID бота, отметки повторов и last_poll_at — служебные записи `telegram:*` в meta,
поэтому входят в существующие резервные копии. База связывается с одним ботом: замена токена
того же бота допустима; подключение другого бота требует отдельной базы. При восстановлении старой
копии возможен откат offset; Telegram уже подтверждённые обновления не вернёт. Outbox из старой
копии также не обеспечивает отсутствие повторов реальных внешних действий — оператор должен
сверить состояние, прежде чем разрешать отправку.

Источники: [getUpdates](https://core.telegram.org/bots/api#getupdates),
[получение обновлений и срок хранения](https://core.telegram.org/bots/api#getting-updates),
[sendMessage](https://core.telegram.org/bots/api#sendmessage).
