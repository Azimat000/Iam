# Iam — ядро цифровой личности

Проект ведёт Claude Code по плану `docs/PLAN.md` (источник истины). Работа разбита на **срезы S00–S29, один срез = одна сессия**. Память между сессиями — файлы этого репозитория, не контекст чата. Пользователь не обязан ничего пересказывать: всё нужное для продолжения лежит здесь.

Язык: общение и документы — русский, простыми словами; идентификаторы в коде — английские.

## Протокол сессии (выполнять всегда, по порядку)

**1. Старт.**
- `python3 tools/memory.py brief` — какой срез текущий, какие барьеры, последние записи журнала.
- **Всегда** `python3 tools/memory.py sync`: сессия могла стартовать с другой ветки. Команда сравнивает счётчик `revision` в `docs/state.json` со всеми ветками `origin/claude/*` и, если где-то память свежее, печатает команду `git checkout -B <ветка> <свежая>`. Выполни её (если нет несохранённых правок) и повтори `brief`. Не начинай срез на устаревшей памяти. Если в репозитории нет `CLAUDE.md`/`docs/state.json` вовсе — найди ветку `origin/claude/*` с `docs/state.json` (`git ls-tree`/`git show`) и переключись на неё.
- Открытые барьеры (их печатает `brief`) — сообщи пользователю в начале ответа, если какой-то из них скоро станет блокирующим.
- Прочитай `docs/slices/<срез>-*.md` целиком, затем только те разделы `docs/PLAN.md` и файлы кода, на которые он ссылается. Не читай весь репозиторий.
- Если пользователь в сообщении просит что-то другое (вопрос, правка) — сначала сделай это, потом вернись к протоколу; срез не теряется.
- `python3 tools/memory.py start <срез>` (откажет, если не закрыты зависимости, открыты блокирующие барьеры или уже есть срез в работе).

**2. Работа.**
- Делай только то, что описано в разделе «Что делаем» среза, и только в файлах из «Границ файлов». Выход за границы — запиши причину в `docs/DECISIONS.md`.
- **Контрольные точки.** Контейнер эфемерный: после каждого крупного шага (и минимум раз в ~30 минут работы) запускай `python3 tools/memory.py checkpoint -m "что сделано"` — это журнал + WIP-коммит + push в ветку сессии. Так обрыв не стоит работы.
- Реализуй мелкими шагами, тесты пиши вместе с кодом (`python3 -m unittest discover -s tests -v`; внешних зависимостей в ядре минимум).
- Любое решение, которое нельзя легко откатить или которое меняет план, — запись в `docs/DECISIONS.md` (контекст → решение → последствия).
- Если нужен пользователь (токен, оценка, выбор, запуск на Mac) — это **барьер**: `memory.py gate-add SLICE -m "..." [--blocks-start S..] [--blocks-finish S..]`. Барьеры с `blocks_*` инструмент проверяет сам: `start`/`finish` откажут. Продолжай с независимой частью работы, не блокируй себя. Никогда не выдумывай ответ пользователя и не подменяй живую проверку заглушкой молча — отмечай как «проверено на заглушке».
- Честность статусов: требование получает `verified` только когда есть свидетельство (результат запуска проверки, запись, артефакт). Нет свидетельства — `planned`/`implemented`. Невыполненное остаётся видимым.

**3. Закрытие среза (обязательно, даже если контекст на исходе).**
- Запусти все тесты и `python3 tools/memory.py check`. Если красное — срез не закрыт.
- Независимая проверка: запусти подагента (`Agent`, general-purpose) с задачей «просмотри `git diff` среза против его раздела «Границы файлов» и «Проверки», найди нарушения границ и непроверенные заявления». Исправь найденное.
- Заполни раздел «Итог» в файле среза (что сделано, как проверено, что не сделано, что унаследовать следующему срезу), удали маркер `ИТОГ-НЕ-ЗАПОЛНЕН`.
- Допиши обновления в `requirements.toml` (когда он появится после S01) и `docs/DECISIONS.md`.
- `python3 tools/memory.py finish <срез> -m "итог одной-двумя фразами"` — закроет срез, переключит текущий на следующий, обновит `docs/STATE.md` и журнал.
- Коммит (сообщение по-русски, первая строка — `Sxx: что сделано`) и `git push -u origin <ветка сессии>`. Повтор при сетевой ошибке: 2/4/8/16 с. PR не создавать, пока пользователь не попросит.
- Финальное сообщение пользователю — **объяснение среза простыми словами**: зачем он нужен, что теперь работает и как это увидеть, что проверено и чем, что проверить не удалось, какие барьеры ждут его действий, что будет в следующем срезе. Без жаргона; термины — с расшифровкой в скобках.

## Если сессия оборвалась на полпути
Срез остаётся `in_progress`, работа — незакоммиченной или частично закоммиченной. Следующая сессия: `brief` покажет это; выполни `git status`/`git log`, оцени сделанное по «Что делаем», допиши недостающее, не начиная срез заново. Если в `docs/JOURNAL.md` нет записи о ходе работы — это норма: вноси заметки через `memory.py log -m "..."` в конце каждого крупного шага, чтобы обрыв был дешёвым.

## Жёсткие правила проекта (из плана)
- Модель только **предлагает**; состояние и память меняет проверяющее ядро (`StateController`). Ответ с устаревшей версией состояния не применяется.
- Технический архив недоступен обычному извлечению воспоминаний. Восстановление из архива — отдельное вмешательство оператора.
- «Человек сообщил X» ≠ «X истинно». Источник, время, тип происхождения, связи, история — у каждой значимой записи.
- Непрочитанное сообщение не влияет на решение. Сообщение не меняет технические права.
- Секреты (токены Telegram, авторизация Codex) — никогда в репозиторий, экспорт, логи. Только переменные окружения/внешние файлы вне репозитория.
- Хранилище постоянной личности отдельно от экспериментального; тестовые биографии туда не переносятся.
- Нельзя объявлять выполнение без подтверждённого результата действия.
- Не ослаблять тест, чтобы он прошёл; не пропускать тесты. Если тест неверен — исправь с записью в DECISIONS.md.

## Окружение разработки (допущение A2)
Облачный контейнер: нет Docker-демона, Codex, Telegram, подписки. Всё, что требует их, делаем на заглушках + контрактных тестах и готовим скрипты для запуска на Mac пользователя (барьеры). Стек: Python 3.13 (стандартная библиотека + SQLite 3.45 с FTS5). Сторонние пакеты (FastAPI и др.) ставить только в срезе, где они нужны, и фиксировать версии.

## Карта репозитория
- `docs/PLAN.md` — план (источник истины) · `docs/ROADMAP.md` — карта срезов и логика разбиения
- `docs/state.json` — машинное состояние (менять только `tools/memory.py`) · `docs/STATE.md` — его отображение
- `docs/slices/Sxx-*.md` — описание каждого среза · `docs/JOURNAL.md` — журнал (только дописывать)
- `docs/DECISIONS.md` — принятые решения · `requirements.toml` — реестр требований (создаётся в S01)
- `tools/` — служебные инструменты · `src/iam/` — ядро (с S04) · `tests/` — тесты
