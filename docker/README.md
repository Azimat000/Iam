# Изолированный исполнитель Codex

Активный образ — Codex CLI `0.166.0`, модель — только `gpt-6-luna`. Вход по подписке ChatGPT, автоматического перехода на API или другую модель нет. Исторические файлы `scripts/claude/` не относятся к этому запуску.

```sh
docker build --platform linux/arm64 -t iam-codex:1 docker/
docker compose -f docker/compose.yaml up -d
```

Образ `node:22-bookworm-slim`, архитектура `linux/arm64`, пользователь `10001:10001`. Версия npm-пакета закреплена. Основа закреплена по идентификатору `sha256:4b150b48b4116e2a22f2c39cc27025fbf4f153e2078fd3b14d159fdb5c7279da`; обновление требует явной правки. `launch.cjs` и публичная `response.schema.json` — единственные копируемые файлы.

Команду запуска собирает `iam.providers.codex.docker_run`: корень только для чтения, все дополнительные права убраны, запрещено повышение прав, заданы пределы памяти, процессора и процессов. `/home/codex`, `/tmp`, `/work` — отдельные временные хранилища. Папки компьютера и Docker socket не монтируются. Рабочий каталог пустой, общие настройки, плагины и правила пользователя туда не попадают.

Пароль входа не передаётся через параметры команды, переменные среды или образ. Адаптер читает внешний файл `auth.json` с правами `600`, оставляет только данные входа подписки и посылает JSON `{auth,prompt}` через стандартный ввод. Launcher создаёт временный `CODEX_HOME/auth.json` с правами `600`, запускает CLI без оболочки и удаляет файл после завершения. Обмен с CLI не требует файлов запроса на компьютере; запросы ядра сохраняются в его обычном техническом журнале. JSONL ответа идёт в адаптер; сырой stderr CLI не публикуется. Обновление токенов в контейнере не сохраняется на компьютере: внешний файл иногда нужно обновить после нового входа.

Сеть `iam-sandbox` внутренняя. Единственный выход — `iam-proxy`, подключённый также к `iam-egress`. Порты наружу не открываются. Образ Squid закреплён по digest; он получен из Google-managed кэша Docker Hub `mirror.gcr.io`, поскольку прямое скачивание Docker Hub в этой среде прерывалось TLS-таймаутами. Squid разрешает HTTPS CONNECT на точные имена `chatgpt.com`, `auth.openai.com`, `api.openai.com`, затем запрещает всё остальное. Последний адрес разрешён для совместимости CLI; API-ключи не принимаются адаптером. Записи запросов и кэш отключены. Список не утверждается как исчерпывающий для всех будущих версий: провал живого входа требует отдельной проверки причины.

Проверка: [scripts/codex/README.md](../scripts/codex/README.md). Живая проверка на Mac выполнена 2026-10-30: `docs/evidence/codex-isolation.json`. Повторяйте её после изменения образа, сети или авторизации. Встроенная изоляция Codex не должна требовать ослабления Docker: не добавляйте privileged, socket, host network или seccomp=unconfined для обхода ошибки.

Источники версии и поведения: [npm 0.166.0](https://www.npmjs.com/package/@openai/codex/v/0.166.0), [вход](https://learn.chatgpt.com/docs/auth), [неинтерактивный запуск](https://learn.chatgpt.com/docs/non-interactive-mode).
