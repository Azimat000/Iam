# Ручной сеанс Iam на Mac

Оператор запускает панель, наблюдает сеанс и останавливает его. Постоянная история «Общительная» хранится в `~/.local/share/iam/permanent`. Оператор разговаривает с ней в личном чате Telegram. Технические решения, например изменение прав, оформляются в панели.

## Перед первым сеансом

1. В Terminal откройте актуальную рабочую папку. Нужны Python 3.13 и запущенный Docker на Mac с Apple Silicon. Установите зависимости проекта в отдельное окружение.

   ```zsh
   cd "$HOME/.iam-evidence/s25-integration-20261105/workspace" || return 1
   python3 -m venv .venv
   .venv/bin/python -m pip install -e .
   ```

2. Проверьте наличие образа `iam-codex:1` и работающего посредника `iam-proxy`. Если их нужно подготовить, используйте [инструкцию Docker](../docker/README.md). Для входа используйте отдельный файл подписочной авторизации IAM вне проекта. Панель сохраняет обновления в этом файле при запуске с `--persist-codex-auth-updates`. При необходимости обновите отдельный вход по [инструкции восстановления](../scripts/experiments/README.md#восстановление-входа-после-g13).
3. Личный обмен с Telegram проверен. Числовой ID оператора и перевыпущенный токен сохранены на этом Mac в `~/.local/share/iam/operator`. При следующей замене токена вводите его только в скрытый запрос Терминала. [Результаты первых сеансов](evidence/S27-first-sessions.md).

## Запуск и остановка

На этом Mac в каталоге `personas` должна быть ровно одна постоянная база. Запустите панель так. В запросе «Файл входа» введите полный путь к отдельному файлу авторизации IAM.

```zsh
(
  cd "$HOME/.iam-evidence/s25-integration-20261105/workspace" || exit 1
  iam_dbs=("$HOME/.local/share/iam/permanent/personas/"*.db(N))
  if (( ${#iam_dbs} != 1 )); then
    printf 'Ожидается ровно одна постоянная база Iam.\n' >&2
    exit 1
  fi
  iam_id_file="$HOME/.local/share/iam/operator/telegram-user-id"
  IFS= read -r iam_user < "$iam_id_file" || exit 1
  read -r 'iam_auth?Полный путь к файлу входа Codex: ' || exit 1
  iam_token_file="$HOME/.local/share/iam/operator/telegram-bot-token"
  if [[ -f "$iam_token_file" && ! -L "$iam_token_file" && -O "$iam_token_file" &&
        "$(stat -f '%Lp' "$iam_token_file")" == 600 ]]; then
    IFS= read -r TELEGRAM_BOT_TOKEN < "$iam_token_file" || exit 1
  else
    read -rs 'TELEGRAM_BOT_TOKEN?Токен Telegram: ' || exit 1
    printf '\n'
  fi
  export TELEGRAM_BOT_TOKEN
  SSL_CERT_FILE=/etc/ssl/cert.pem .venv/bin/python -m iam.panel \
    --db "$iam_dbs[1]" --codex-auth-file "$iam_auth" --persist-codex-auth-updates \
    --telegram-user "$iam_user"
)
```

Откройте [локальную панель](http://127.0.0.1:8765/). Пока сеанс остановлен, откройте «Расход и ошибки». Успешный опрос Telegram должен иметь свежую отметку времени. Бот принимает сообщения также на паузе. Если приёмник не работает, Telegram хранит ожидающие обновления не дольше 24 часов. [Документация Bot API](https://core.telegram.org/bots/api#getting-updates).

1. Для обычного общения нажмите «Начать разговор». Разговор идёт до вашей ручной паузы или завершения, без ограничения30 минут/10 обращений. Если прежний сеанс уже идёт или на паузе, нажмите «Продолжить без ограничений»: история, сеанс и счётчик сохранятся. Для запланированных проверок раскройте «Проверочный сеанс с лимитами» и нажмите «Запустить сеанс» (до30 минут/10 обращений). Любой запуск исполнителя, включая ошибку формата, учитывается в расходе.
2. Отправьте нейтральное сообщение в личный чат бота. В разделе «События» видно, что сообщение пришло. Если личность сама выбрала чтение, в журнале появится `input.read`. Ответ не обязателен. Отправка считается подтверждённой после ответа Telegram.
3. Нажмите «Поставить на паузу». Запишите показание времени жизни и расход. После завершения текущего обращения нажмите «Продолжить сеанс». Пауза не расходует время жизни и не выдаёт новый бюджет. «Завершить сеанс» закрывает сеанс. Чтобы остановить саму панель, нажмите Ctrl+C в Терминале после завершения сеанса.
4. Для второго ручного сеанса используйте ту же базу. Сверьте личность, мир, намерения и время жизни на вкладках «Состояние» и «Мир». Запишите время начала и окончания, события паузы/возобновления, расход, исходы сообщений и ошибки для каждого сеанса. «Сеанс» показывает последние события и расход. «Расход и ошибки» показывает ошибки и состояние Telegram.

## Когда что-то пошло не так

| Что видно | Что сделать |
|---|---|
| Ошибка входа Codex | Завершите сеанс и панель. Обновите отдельный вход IAM. Затем проверьте его по [инструкции Codex](../scripts/codex/README.md) и запустите новый сеанс. |
| Достигнут лимит сеанса или подписки | Различите причину на вкладке «Расход и ошибки». В обычном разговоре лимитов приложения нет. Из проверочного сеанса можно перейти в разговор кнопкой «Продолжить без ограничений» или завершить его. При лимите подписки дождитесь восстановления доступа по условиям вашей подписки. |
| Неизвестен исход сообщения | Сначала проверьте личный чат и запись об отправке. Потерянное подтверждение может означать, что сообщение уже дошло. |
| Ошибка Telegram или давний успешный опрос | Сверьте сеть, токен и наличие только одного приёмника. Перезапустите панель после проверки. Для ошибки сертификата используйте системный набор из команды запуска. |
| Мало места или база не проходит проверку | Остановите панель. Освободите место вне папки личности или подключите другой диск. Если база повреждена, проверьте снимок и восстановите его в отдельную папку. |

## Копия и отдельное восстановление

1. На вкладке «Копии и восстановление» создайте снимок. В локальном каталоге `~/.local/share/iam/permanent/backups` хранятся три последних снимка. Каждый снимок состоит из файлов `.db` и `.json` с одинаковым именем.
2. Для проверки восстановления остановите сеанс, дождитесь окончания обращения и воспользуйтесь кнопкой «Восстановить в отдельную базу». Для проверки из Терминала остановите панель, затем укажите путь к снимку. Команды создадут отдельную базу и проверят её.

   ```zsh
   (
     read -r 'iam_snapshot?Полный путь к файлу снимка .db: ' || exit 1
     iam_recovery=$(mktemp -d "$HOME/.local/share/iam/recovery.XXXXXXXX") || exit 1
     .venv/bin/python -m iam.cli verify "$iam_snapshot" || exit 1
     .venv/bin/python -m iam.cli restore "$iam_snapshot" --to "$iam_recovery" \
       --reason "Проверка восстановления S27" || exit 1
     iam_restored=("$iam_recovery/"*.db(N))
     (( ${#iam_restored} == 1 )) || exit 1
     .venv/bin/python -m iam.cli verify "$iam_restored[1]"
   )
   ```

3. Сохраните внешний экземпляр одним из двух способов: скопируйте пару `.db` и `.json` на отдельный зашифрованный носитель либо поместите их в зашифрованный архив и загрузите в выбранное облако. Пароль к архиву сохраните доступным без этого Mac, отдельно от архива. Проверьте внешний `.db` через `.venv/bin/python -m iam.cli verify` и повторите пробное восстановление с этого носителя в новый каталог. Зафиксируйте дату и результат. Резервная копия содержит личную историю. Если нужно заменить рабочую базу восстановленной, сначала сохраните текущую базу отдельно и сверьте уже отправленные сообщения в Telegram. Позиция опроса в старой копии могла отстать.

## Проверенный облачный вариант: iCloud (D-110)

Копия от 11 ноября 2026 года находится в iCloud Drive → `IAM Backups` → `IAM-backup-20261111-113238.tar.gpg` (809 216 байт). Она содержит всю историю до события №108. Пароль храните в подтверждённом вами месте вне Mac; не присылайте его в чат и не кладите рядом с архивом. [Проверка скачивания и восстановления](evidence/S27-icloud-backup.md).

Для новой копии используйте новый снимок и отдельное имя архива; рабочую базу не синхронизируйте через облачную папку. Убедитесь, что передача в iCloud закончилась. Для проверки именно облачного файла выберите в Finder «Удалить загрузку», дождитесь «В iCloud», затем скачайте его снова. «Удалить загрузку» относится только к локальному содержимому; «Переместить в Корзину» для проверки не используется.

После потери Mac скачайте архив на другой компьютер, установите GnuPG и получите код IAM из сохранённого репозитория. Расшифруйте архив командой ниже; GPG запросит сохранённый пароль. Внутри лежат `.db` и `.json` манифеста. Извлеките их в новую папку, проверьте `.db` командой `iam.cli verify`, восстановите в ещё один отдельный каталог командами предыдущего раздела и повторите `verify`. Рабочую базу заменяйте только после сверки истории и отправленных сообщений.

```zsh
gpg --output iam-recovered.tar --decrypt IAM-backup-20261111-113238.tar.gpg
```
