# S25. Первая контрольная точка совместной приёмки

Исходная версия `ebd99c2` из основной ветки включает принятый S24. Проверки S25 работают на новой экспериментальной базе с постоянными модулями, которыми пользуется панель. Подготовленные ответы поставляет `ScriptedProvider`, а предложения, записи и исходы проверяет настоящее ядро.

## Технические свидетельства

| Условие | Что проверено |
| --- | --- |
| Сбой во время действия | 100 настоящих остановок `SIGKILL`, по 25 в четырёх точках. Проверены начало сеанса, сохранённый резерв вызова, открытая транзакция записи работы и момент после вычисления результата до подтверждения. Ранее принятые чтение, работа и намерение переживают каждый сбой. Прерванные действия получают неизвестный исход один раз, без подтверждения, квитанции или новой работы. |
| Восстановление копии | Восстанавливается отдельная база с новой эпохой и отметкой в журнале. Сохраняются принятые чтение, работа и намерение. Работа после копии остаётся в исходной базе и отсутствует в восстановленной. |
| Контроли из общего прошлого | Полный режим и две ветви с выключенной памятью или мотивацией получают копии одной закрытой базы. До разветвления совпадают состояние и события. В полном режиме подготовленное правило использует основание и продолжает работу. Обе контрольные ветви выбирают отдых. При отключении мотивации обычный опыт остаётся доступен, а при отключении памяти закрыты также его производные в каталоге работ. |
| Сквозная связь | Прочитанный материал становится основанием эмоциональной оценки и мотивационной гипотезы. После открытия базы поздний запрос содержит эти основания и незавершённое намерение. Проверены новая сохранённая работа и принятая запись самомодели со ссылкой на неё. |
| Панель | 11 маршрутов в Chromium на ширинах 320, 390 и 1366 пикселей. На каждом ответ 200, один заголовок первого уровня, нет горизонтального переполнения и нарушений по проверенным правилам axe. Проверены видимый фокус и раскрытие раздела клавиатурой. Через настоящие формы созданы и восстановлены копия в отдельную базу, эпоха открытой базы сохранилась. Данные для просмотра преимущественно пустые. |

[Тесты постоянного ядра](../../tests/integration/test_persistent_core.py) · [Проверка Chromium](S25-browser.json) · [Сценарий проверки браузера](S25-browser.cjs)

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -p test_persistent_core.py -v
python3 tools/memory.py check
python3 tools/reqs.py validate
python3 tools/scenarios.py validate
```

Для повтора браузерной проверки запустите локальную панель с `--demo` и новым временным файлом базы. Укажите в `IAM_PANEL_URL` её адрес на 127.0.0.1, в `IAM_BROWSER_OUT` существующий каталог для отчёта, в `IAM_PLAYWRIGHT` путь к модулю Playwright, в `IAM_CHROMIUM` путь к браузеру, в `IAM_AXE` путь к `axe.min.js`. Запустите `node docs/evidence/S25-browser.cjs`.

## Матрица обязательных сценариев

Строки отмечают текущие свидетельства и объём оставшейся интеграционной проверки. Ранее принятые модульные проверки помогают подготовить случаи, но сами по себе не закрывают строку S25.

| Сценарий | Что осталось подтвердить в S25 |
| --- | --- |
| `action_crash` | Сохранность и честный неизвестный исход подтверждены новым хаос-тестом. Сохранить трассу по условиям сценария для итоговой матрицы. |
| `restore_backup` | Восстановление соединённого состояния подтверждено новым тестом и через браузер. Сверить остальные условия сценария и приложить трассу. |
| `pause_restart` | Тесты прерывания и сквозной истории подтвердили сохранность. Добавить явное сравнение собственного времени до паузы и после возобновления на том же ядре. |
| `memory_off` | Технический контроль из общей истории проходит с подготовленным правилом выбора. Повторить с рабочей моделью, проверить исход и отсутствие обходной утечки. |
| `no_new_messages` | Есть подтверждённые чтение и запись без сообщений в подготовленной истории. Подтвердить собственный выбор двух разных занятий рабочей моделью. |
| `new_interest` | Гипотеза интереса и ссылка на опыт сохраняются в технической истории. Проверить возникновение и использование интереса в живой серии. |
| `self_reflection` | В технической истории рефлексия основана на результате. Добавить проверки попытки углубления и смены черты на полном сценарии. |
| `auth_error_or_limit` | Перенести тесты ошибок авторизации и лимитов из `providers/test_budget.py` на соединённый цикл. |
| `correct_old_fact` | Проверить замену основания и поздний выбор с поправкой в памяти и убеждениях. |
| `creator_refusal` | Перенести цепочку просьба → отказ → поздний выбор из `creator_bridge/test_requests.py` на общий сценарий. |
| `forgetting` | Подтвердить, что забытый текст не возвращается через мотивацию, отношения, самомодель или каталог работ. |
| `model_swap` | Сохранить целую историю при смене тестового провайдера и проверить, что поздний ответ прежнего отклоняется. |
| `no_tool` | Проверить выбор ожидания, отказа либо просьбы и отсутствие неподтверждённого исполнения. |
| `one_situation_diff_experience` | Подать один нейтральный сигнал на две разные подготовленные истории и сравнить видимые основания и фактическое действие. |
| `repeat_criticism` | Прогнать чтение и повтор критики, оценку эмоции, прежнее убеждение и позднее действие. |
| `repeat_own_thought` | Проверить точный повтор на постоянном мире и отследить оценку интереса и поздний выбор. |
| `replayed_or_stale_result` | Проверить повтор и запоздалый ответ в одном соединённом сценарии с разными версиями. |
| `rights_by_message` | Проверить на общем сценарии, что прочитанное сообщение и социальная интерпретация не меняют разрешения. |
| `unread_message` | Проверить отсутствие непрочитанного текста во всех частях запроса и в производных состояниях. |

## Дальнейшая приёмка

Техническая история и контроли проверяют передачу основания и работу ограничений. Они не свидетельствуют о добровольном выборе GPT-6-Luna. Для приёмки нужны фиксированные пять разных живых историй, два независимых возврата к добровольному намерению, подтверждённое достижение исходного критерия и живые контрольные ветви. До серии фиксируются входы, версии, условия остановки и бюджет из [контракта S25](../COMPLETION.md#поведенческий-минимум-s25). Живая серия ещё не запускалась. Повышения статусов требований и перехода к S26 на этой контрольной точке нет.
