# Предложение следующего шага: явный необязательный формат замысла

Это подготовленное предложение, **не разрешение на новую серию**. D-076 завершился отрицательно, D-077 исправляет конкретный разрыв ссылок. Новых обращений по этому документу нет.

## Основание и гипотеза

В A-deliberate модель описала будущую проверку в обычном тексте работы, но не создала intention. Ядро принимает полноценный create из того же состояния. В текущем внешнем формате все тела предложений спрятаны в строке body_json, и native-схема не описывает обязательные поля конкретного create. Подтверждено различие представлений; причинная роль этого различия не доказана.

Следующая гипотеза относится к представлению ответа, а не к характеру или числу возможностей. В отдельном экспериментальном адаптере сохранить прежние предложения немедленного действия и добавить отдельное **необязательное** поле future_intention. Оно либо null, либо полное явно выбранное моделью предложение: rationale, cites и body с op, intention_id, text, criterion, project_id, operation. Все содержательные поля модель заполняет сама. Никаких примерных целей, тем, критериев и готовых значений в запросе нет.

Адаптер может только дословно преобразовать явно заполненный объект в прежнее предложение intention. Он не извлекает цель из текста работы, не дописывает критерий, не превращает интерес в цель и не создаёт ничего при null. Проверяющее ядро и его требования к доступному собственному опыту, версии, правам, исходному критерию и позднему результату неизменны. Отдых, пустой список действий и null допустимы одновременно. Положительный ответ не получает премии за число целей.

## Условия возможного исполнения

Сначала — проверка совместимости экспериментальной схемы с выбранным исполнителем и локальные отрицательные проверки: null не создаёт цели; неполный объект не исправляется адаптером; скрытое/подготовленное основание не объявляется живым опытом; запрещённые ссылки и устаревший ответ не применяются; сочетание действия с целью сохраняет прежние лимиты. Отдельно проверить, что старый формат и новый явный объект дают ядру одинаковое полное предложение, когда модель действительно его выразила.

Только после отдельного решения пользователя: одна предзарегистрированная диагностика из тех же реальных A/E, по3ветви (прежний body_json, явный необязательный объект, объект с memory_off), максимум6решений/12физических обращений, без ремонта и повторов до успеха. Профиль, модель, доступный опыт, лимиты контекста и выхода, история и критерии приёмки прежние. Техническая проверка — один полный цикл, максимум один после подтверждённого дефекта. Точный экспериментальный код, публичная схема, исходные состояния и ID образа фиксируются до вызова.

Это не новая полная приёмка S25 и не автоматическое расширение текущего бюджета. При отсутствии добровольного замысла — остановка с отрицательным результатом, без следующей смены слов/характера/горизонта. При появлении — сначала проверить принятие, а позднее продолжение и завершение остаются самостоятельными невыполненными условиями. Постоянный интерфейс личности не меняется по одному диагностическому успеху.
