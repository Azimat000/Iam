# Переход исполнителя на Codex GPT-6-Luna

Дата: 2026-10-30. Исполнитель — `codex exec`, npm CLI `0.166.0`, Linux/arm64 в Docker на Mac. Пользователь явно подтвердил модель **GPT-6-Luna (`gpt-6-luna`)** после сверки доступного списка; прежнее название «6.1 Luna» уточнено, модель не заменялась без ответа пользователя.

## Что изменилось

Рабочая панель создаёт `iam.providers.codex.CodexProvider`. Внешний файл входа задаётся `--codex-auth-file`; старый флаг `--claude-token-file` больше не принимается. Все назначения запроса используют выбранную Luna, без автоматического перехода на сильную модель или API. Общие состояние, сеансы, постоянный бюджет и мир сохраняются. Старые модули/тесты Claude оставлены как история совместимости, в рабочий запуск панели они не входят.

Модель получает только задачу, отобранный контекст, допустимые предложения/возможности и предел ответа. Для строгого вывода Codex используется схема `{proposals:[{kind,rationale,cites,body_json}],explanation}`: все поля обязательны, дополнительные поля запрещены. Адаптер разбирает JSON тела и проверяет прежнюю схему предложения ядра. Идентификаторы предложений и эхо запроса назначаются локально. Wire-схема в образе совпадает с константой адаптера; общий формат ядра не менялся.

JSONL считается успешным только при корректной последовательности событий, ровно одном итоговом сообщении и завершённом ходе. Ошибки, незавершённый поток, повреждённый JSON, дубли полей, неизвестные виды событий и несколько итогов не дают применить ответ. Любая попытка инструмента делает весь ответ непригодным, даже если дальше пришёл корректный JSON. Формат исправляется не больше одного раза; повтор получает оставшуюся часть общего срока. Ошибки авторизации, подписочного лимита, времени и бюджета сохраняют свои классы, чтобы сеанс правильно встал на паузу.

Авторизация — только подписка ChatGPT. Из внешнего файла `auth.json` с правами 600 берутся только необходимые поля `auth_mode` и `tokens`; API-ключи, символические ссылки и файлы внутри репозитория отклоняются. Данные входа идут в stdin контейнера вместе с запросом, не в argv, окружении, образе или журнале. Bootstrap пишет временный файл входа в tmpfs, запускает CLI без оболочки и удаляет файл. Корень только для чтения, UID/GID 10001, capabilities отсутствуют, повышение прав запрещено, лимиты CPU/памяти/процессов включены. Личные папки и Docker socket не подключаются. Чистые HOME/CODEX_HOME/рабочий каталог исключают пользовательские плагины, MCP, навыки и правила. Включены read-only sandbox, ephemeral, ignore-user-config/ignore-rules, отключены hooks/shell_tool/multi_agent.

Сеть исполнителя внутренняя. Squid разрешает точные TLS-адреса `chatgpt.com`, `auth.openai.com`, `api.openai.com` и запрещает остальные; прямой выход в обход посредника не работает. Настройки HTTPS и WebSocket proxy передаются явно. Node и Squid закреплены по digest, CLI — точной версией. Публичный кэш Google использован для того же образа Ubuntu Squid после TLS-таймаутов Docker Hub. Глобальные настройки Docker не менялись; отсутствующий docker-credential-desktop обойдён временным пустым конфигурационным каталогом только для сборки/скачивания.

Полная безопасная трасса живого цикла — `docs/evidence/codex-core.trace.json`. Она содержит только искусственную техническую ситуацию и проверена сканером по значениям реальных токенов до сохранения. Исходная экспериментальная база — локально в `data/codex-live-20261030`, отдельно от постоянной личности и вне Git.

Первый живой проверочный запрос был отклонён адаптером: модель верно сослалась на переданный inp_…, но схема предложения принимает только evt_/mem_. Запрос проверки приведён к полной схеме request, а уведомление в общем Cycle теперь ссылается на реальное событие `input.arrived`, не на input_id. Это устраняет ту же несовместимость при настоящем входящем сообщении, сохраняя запрет передачи непрочитанного текста. Добавлена проверка `tests/providers/test_codex_integration.py`. Повторная живая проверка и полный цикл прошли.

Независимое чтение интеграции нашло потерю классов ошибок в обёртке A, возможность перезаписать auth через жёсткую ссылку отчёта и недостаточную проверку mounts/CPU. Основной агент проверил замечания по исходникам, исправил их и добавил отрицательные проверки: подмена tmpfs внешней файловой системой и отсутствие CPU quota дают FAIL, hardlink отчёта не меняет auth, типы ошибок/бюджета сохраняются. Отчёт записывается атомарной заменой. Учёт каждого запуска CLI и пауза во время ожидания покрыты существующими тестами панели с новым FakeCodex; прежние утверждения не ослаблялись.

## Как повторить

Сборка/посредник и проверка описаны в `docker/README.md` и `scripts/codex/README.md`.

```sh
docker build --platform linux/arm64 -t iam-codex:1 docker/
docker compose -f docker/compose.yaml up -d
PYTHONPATH=src .venv/bin/python scripts/codex/verify.py \
  --auth-file "$HOME/.codex/auth.json" \
  --output-dir "$HOME/.iam-evidence/codex-live" --live
```

Запуск существующей базы через панель:

```sh
PYTHONPATH=src .venv/bin/python -m iam.panel \
  --db /absolute/path/to/persona.db --codex-auth-file "$HOME/.codex/auth.json"
```

Панель слушает 127.0.0.1. Постоянная личность этой проверкой не создаётся; живой цикл использовал отдельную экспериментальную базу. Демонстрация `--demo` по-прежнему не вызывает модели и Telegram.

## Источники и ограничения

Неинтерактивный режим и схема: [официальная документация Codex](https://learn.chatgpt.com/docs/non-interactive-mode). Авторизация и перенос auth.json: [Authentication](https://learn.chatgpt.com/docs/auth). Параметры CLI: [CLI reference](https://learn.chatgpt.com/docs/cli/reference). Модель: [официальный каталог](https://developers.openai.com/api/docs/models). События JSONL: [исходник OpenAI Codex](https://github.com/openai/codex/blob/main/sdk/typescript/src/events.ts). Дополнительно проверены help собранного CLI и реальный ответ подписки.

Обновлённые токены внутри временного контейнера не переносятся в исходный файл компьютера. При истечении его авторизации нужно обновить внешний файл обычным входом Codex; автоматического обхода через API нет. Список разрешённых хостов проверен с этой версией, не обещает совместимости со всеми будущими изменениями сервиса. Проверка no_action доказывает работоспособность исполнителя/ядра, но не качество личности и не прохождение смысловых утверждений восьми сценариев. Политики данных подписки (G09), живой Telegram (G02), сравнение архитектур S13–S17 остаются отдельными задачами.

Итог общего прогона тестов и покрытия добавляется после завершения проверки текущих исходников.
