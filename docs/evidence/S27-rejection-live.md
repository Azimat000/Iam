## Постановка до отправок

До сообщений в JOURNAL закреплены отдельная экспериментальная база, один `getMe`, не более четырёх `getUpdates`, не более пяти служебных сообщений через Telegram UI, ноль Bot API `sendMessage`, ноль обращений к модели. Проверяются три условия: разрешённый аккаунт в личном чате; другой числовой отправитель в личном чате; разрешённый аккаунт в группе. Постоянный список разрешённых отправителей не меняется. При неожиданном входящем проверка останавливается без следующего подтверждения получения.

Использованы два уже вошедших аккаунта пользователя. Создана отдельная группа `Iam R158 test 2026-11-11`, только основной аккаунт и бот, два участника. Сообщения другим людям и в существующие группы не отправлялись. После проверки Telegram возвращён на основной аккаунт. Тестовая группа оставлена на месте; права бота не расширялись.

## Что действительно пришло из Telegram

Штатный `Client` получил настоящий ответ Bot API. Проверочный слой сохранил исходные обновления в защищённом локальном каталоге, проверил, что они относятся к этому тесту, и передал **тот же ответ без изменения** штатному `Receiver.poll_once`. Числовые ID и исходные ответы не включены в репозиторий.

| Реальное обновление | Проверка источника и чата | Результат в отдельной базе |
|---|---|---|
| Личное сообщение основного аккаунта | Числовой отправитель в разрешённом списке, `private`, ID чата совпадает с отправителем | Одно `input.arrived`, событие №2, одна строка inbox |
| Создание тестовой группы | Основной аккаунт, `group`, служебное обновление | `system.rejected_sender`, №3 |
| Команда из тестовой группы | Тот же разрешённый отправитель, `group`; ID чата отличается от личного | `system.rejected_sender`, №4, без строки inbox |
| `/start` второго аккаунта | Другой числовой отправитель, `private` | `system.rejected_sender`, №5 |
| Личное сообщение второго аккаунта | Другой числовой отправитель, `private`, ID чата совпадает с ним | `system.rejected_sender`, №6, без строки inbox |

Таким образом, групповой отказ проверен независимо от ограничения отправителя: групповую команду отправил **разрешённый** основной аккаунт. Для чужого отправителя проверен именно **личный** чат.

При вводе положительного контрольного маркера нативный `typeText` потерял буквенную часть: вместо запланированного текста фактически отправлен `-158—20261111`. Перед чтением API это зафиксировано в журнале и проверочном сценарии как точное содержимое единственного разрешённого сообщения. Повторного сообщения не было. Условие приёмки касается источника и вида чата и не менялось. Остальные маркеры вставлены через `paste` и сверены на экране до отправки. Исходная версия проверочного сценария сохранена отдельно.
