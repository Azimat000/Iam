# S10 — панель и ограниченный ручной сеанс

Дата: 2026-10-30. Среда: Mac, Python 3.13.11, SQLite с FTS5. Реальные процессы SQLite/HTTP/Chromium; Claude Code и Telegram заменены тестовыми исполнителями. Секреты и личный аккаунт не использовались. Решение об устройстве и выходах за границы — D-018.

## Как открыть

Из корня проекта с установленными зависимостями `pyproject.toml`:

```sh
PYTHONPATH=src .venv/bin/python -m iam.panel --db /tmp/iam-demo/persona.db --demo
```

Открыть http://127.0.0.1:8765. Демонстрация создаёт отдельную экспериментальную базу, отказывается работать с постоянной личностью и не подключается к Telegram. Если новых событий нет, модель не опрашивается; течение времени само по себе не означает новые занятия.

Зависимости для существующего окружения: `uv pip install --python .venv/bin/python -e '.[dev]'`. Нужен Python 3.13 или новее. Сторонние пакеты закреплены: FastAPI 0.162.0, Starlette 1.10.0, Uvicorn 0.54.0; HTTPX 0.28.1 для тестов. HTTPX поддерживается TestClient, но Starlette предупреждает о будущем переходе на HTTPX2; это не ошибка тестов и не зависимость рабочего сервера.

Для живого исполнителя предусмотрен `--claude-token-file /абсолютный/внешний/claude.env` вместо `--demo`; база уже должна существовать. Для Telegram дополнительно `--telegram-user ЧИСЛОВОЙ_ID`, токен — только в `TELEGRAM_BOT_TOKEN`. Перед живыми сеансами нужны G02/G09/G11. В этой сессии живой режим не запускался.

## Проверка в Chromium

На отдельной демонстрационной базе выполнены кнопками: запуск → пауза → продолжение → завершение → создание копии → восстановление в отдельную базу. Ошибок консоли, неудачных запросов и HTTP-ошибок в финальном сценарии нет. Инъекция axe выполнялась через протокол браузера для диагностики; рабочая CSP продолжает запрещать скрипты.

Исправленные проблемы с повторной проверкой: длинные заголовки на 320 px; доступ к прокручиваемому блоку состояния с клавиатуры; сжатие флажка восстановления на узком экране. Проверка живой HTML-формы также выявила, что Referrer-Policy `no-referrer` превращала Origin POST в null: политика изменена на `same-origin`, проверка точного Origin сохранена, полный путь кнопок повторно прошёл.

Системный шрифт с кириллицей, основной текст 16 px / 24 px, две насыщенности, без внешних загрузок шрифтов. Измерения относятся к локальному приложению без ограничений сети/процессора. Реальные пользовательские показатели скорости, VoiceOver и Windows High Contrast не проверялись. Переключателя тем и других локалей в S10 нет.

## Общие тесты и покрытие

Для CLI-инструментов использован явно измеряемый запуск из раздела «Замер покрытия на этом Mac» в `S09-telegram.md`, с теми же тестами, аргументами и порогами. Имя временного скрипта — `/tmp/iam-s10-explicit-coverage.py`. ВАЖНО: не задавать глобальный `COVERAGE_FILE`: иначе внутренние тесты измерителя из временного проекта получают чужие данные и падают. Не запускать другие замеры одновременно.

```sh
.venv/bin/python -m coverage erase
PYTHONPATH=src .venv/bin/python -m coverage run -p /tmp/iam-s10-explicit-coverage.py
.venv/bin/python -m coverage combine -q
.venv/bin/python -m coverage json -q -o /tmp/iam-s10-coverage.json
.venv/bin/python tools/covcheck.py --json /tmp/iam-s10-coverage.json
python3 tools/memory.py check
python3 tools/reqs.py validate
```

Окончательный полный прогон на неизменных исходниках: **769 тестов за 173.556 секунды — OK**, явно измерено 132 запуска CLI-инструментов. Дополнительно профильный прогон 31 теста панели прошёл. `covcheck --json` завершился с кодом 0: **74 модуля, ниже порога 0**; весь новый критичный код (SessionRunner, учёт состояния, HTTP, защита и владелец цикла) — **100 % строк и ветвей**; шаблоны HTML — 96.6 % строк / 89.1 % ветвей. Полная таблица сохранена в `S10-coverage.txt`. `memory.py check`, `reqs.py validate` и `git diff --check` прошли. Тесты и пороги не ослаблялись. В критичные включены весь SessionRunner, служебный учёт в iam.state, HTTP-формы, локальная защита и владелец цикла панели.

Независимое чтение среза выявило проблему фиксации отправки, перенос старого бюджета и повтор номера решения; исправления повторно проверены агентом. Все исполняемые проверки и браузерный сценарий выполнены основным агентом.
