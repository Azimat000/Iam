# S11 — экспериментальный стенд

Дата: 2026-10-30. Mac, Python 3.13.11, SQLite с FTS5. Использованы настоящие хранилище, StateController и общий цикл; интеллект и внешний мир — учебные заглушки. Claude Code, Telegram и платные сервисы не вызывались.

## Что доступно

```sh
PYTHONPATH=src .venv/bin/python -m iam.experiments \
  --data-root /tmp/iam-experiments \
  --scenario scenarios/experiments/exp_diff_experience.toml \
  --persona scenarios/personas/curious.toml --seed 42
```

Профили: `curious`, `reflective`, `social`. `--memory-off` и `--motivation-off` выключают соответствующую часть во всех ветвях сценария; переключатели `[[run]]` также учитываются. Семя без флага берётся из сценария, по умолчанию 0.

Каждый прогон создаёт новый каталог `experiments/runs/run-NNNNNN/` с собственной экспериментальной `persona.db`, `trace.json` и `manifest.json`. Старые результаты не перезаписываются. Каждая база получает собственный случайный `exp_…`. Постоянные базы не принимаются на вход стенда и не открываются для записи. Профиль и биография из других прогонов не импортируются. Исходное происхождение предыстории сохранено в `content.scenario_origin`, сама запись помечена `simulation_event`.

JSON содержит вход, извлечённую память, мотивы, предложения, реально применённые переходы, ссылки на события-основания, запросы, снимки состояния и полный технический журнал. Журнал содержит сырой вход, включая непрочитанное сообщение; в контекст решения его тело попадает только после явного чтения варианта. Артефакты являются локальными исследовательскими данными и автоматически никуда не отправляются.

После запуска CLI печатает пути трасс и CSV-таблицу сохранённых прогонов. `Results.table()` проверяет SHA256 трассы по манифесту; незавершённый каталог без манифеста не попадает в таблицу. `status=completed` означает окончание исполнения билета, а не прохождение его смысловых утверждений. Пятое `decide` и последующие шаги не исполняются, результат получает `decision_limit`.

## Подключение следующего варианта

Общий интерфейс: `Architecture.name` и `build(runtime) -> Cycle`. Новый экземпляр цикла строится для каждого прогона. `runtime.cycle(provider, **options)` подключает выбранного поставщика предложений к общей памяти, миру, возможностям и ядру. Замена этих общих частей при построении отклоняется. Варианты — доверенный код приложения, а не изолированный исполняемый код недоверенной модели.

Доступны фиксированные часы, отдельный `random.Random(seed)`, текущая ситуация, `model_steps` (очередь заготовленных ответов из билета), явный `read_input`, текущие мотивы. Общая минимальная память учитывает реальные записи и исправления, принятые ядром, независимо от типа события-носителя; архив не извлекается. Отключённая память не читает базу и не создаёт воспоминаний об исполненных действиях. Начальная предыстория в технической базе сохраняется для проверки абляции.

Предыстория S03 задана свободным текстом. Стенд сохраняет её без догадок о смысле: память как память, намерение как начальное `active`, прочие виды как сведения среды. Переходы намерений, пересмотр убеждений, обработка отказа и толкование конфигурации — работа вариантов и будущего ядра. Заготовленные `model`-шаги доступны варианту, учебный Toy их не изображает настоящими ответами.

`world`-шаги создают явно отмеченные события симуляции: начало, попытку и предписанный исход; завершение — только после подтверждения. Они хранятся в отдельном разделе `world.fixture_activities`; выполнение предложений варианта идёт через обычный Cycle и его автомат исходов. Учебный мир не вызывает внешние инструменты.

## Приёмка

| Требование | Свидетельство |
|---|---|
| Одинаковое семя → одинаковые байты | Два повтора всех 8 экспериментальных билетов для каждого из 3 профилей; сравнивается вся трасса, включая внутренние ветви `run` |
| Память влияет на выбор | Тёплая/холодная предыстория и `memory=off` дают разные тела предложений Toy; выключенный опыт отсутствует в запросах |
| Мотивация влияет на выбор | Без мотивов Toy выбирает `no_action` вместо подтверждённого действия; тексты мотивов отсутствуют в запросе |
| Не больше четырёх решений | По 5 `decide` в двух ветвях; исполнены ровно 4 в каждой, последующий вход не принят |
| Базы разделены | Разные файлы/идентификаторы; открытие с ожидаемым постоянным `per_…` даёт PersonaMismatch; запись simulation_event в постоянную базу отвергается ядром |
| Новая память видна | Обычный переход ядра, исправление версии и последующее извлечение текущего значения; отдельная проверка исключения архива |
| Непрочитанное не влияет | Контрольная фраза есть только в техническом журнале; нет её в запросах, памяти решения и состоянии, нет input.read |
| Ядро проверяет предложения | Недоступное действие отклонено; подтверждения выполнения нет |
| Сравнение ошибок повторяемо | Два одинаковых неверных ответа дают одинаковые трассы, ошибки формата и отказ сохранены |
| Тексты не искажаются | Литералы вида evt_… в сообщениях, содержимом памяти и параметрах сохраняются; разные литералы не дают ложного равенства |

Технические ID канонизируются только после обнаружения в структурных полях журнала; связанные ссылки остаются согласованными. Хеши служебных ключей ошибок получают последовательные псевдонимы. Пользовательский текст, содержимое памяти, параметры, мотивы и объяснения не канонизируются. Исходные технические ID остаются в SQLite; `trace.json` не предназначен для восстановления базы.

Профильная проверка: `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/experiments -q` — 30 тестов, OK. Проверка отсутствия фреймворков обучения анализирует импорты `src/` и зависимости проекта.
