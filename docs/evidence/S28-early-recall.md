## Диагноз и изменение

Пустой запрос после чтения выбирал свежие записи. Сам прежний полнотекстовый поиск требовал все слова вопроса. Новый запрос берётся из показанного окна доступной прочитанной записи; лексический поиск учитывает отдельные слова, их редкость среди доступных записей и близкие окончания. Соседние реплики добавляются отдельно с прежним происхождением в существующий лимит, без объявления соседства доказанным ответом. Полный архив, непрочитанное, забытые тексты и старые версии не возвращаются.

Результаты проверок и живой серии будут записаны после фактического выполнения. Общая естественность общения ещё не подтверждена.

## Проверка сохранённого провала без модели

Взяты только192 доступные записи версии1, созданные до события1926, из проверенной копии2010 D-118. При прежнем пустом запросе выбираются пять свежих записей без перчатки. При исходном вопросе1927 новый поиск возвращает ранний вопрос о музее и её ответ с одинокой перчаткой; ответ присутствует и в окончательном контексте. Модель не вызывалась, результаты к личности не применялись. Ограничение: это повтор извлечения и сборки контекста, не полный исторический запуск цикла; прочее состояние опыта остаётся от копии2010. Артефакт replay-retrieval.json.

При разработке адресный тест выявил несовместимость замены точного поиска ассоциативным: запрос «3 марта» начал находить исправленную запись «5 марта» по общему слову. Тест сохранён без ослабления. Решение: точный retrieve сохраняет прежний контракт, отдельный recall используется только в выборе после input.read. Это кандидатные воспоминания с исходным текстом, не утверждение о совпадении всех слов. Первый диагностический helper также был исправлен: get_event принимает номер события, для его идентификатора нужен find_event; ошибочный запуск не считается проверкой.
