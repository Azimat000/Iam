# Совместимость экспериментального nullable object, D-078

Read-only исследователь прочитал официальные источники через доступные бесплатные инструменты и Kimi; новых IAM live-вызовов при исследовании не было.

[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) поддерживает object/array/enum/pattern, требует required для всех полей и additionalProperties:false для каждого объекта. Nullable прямо показано массивом типов на примере string/null; применение object/null — вывод из совместного описания поддерживаемых типов, не отдельный проверенный пример. Корневой объект остаётся обычным object. Схема мала и не приближается к опубликованным ограничениям вложенности/размера. body_json прежних предложений остаётся строкой.

[Официальный тест Codex](https://github.com/openai/codex/blob/main/codex-rs/exec/tests/suite/output_schema.rs) проверяет передачу --output-schema как strict JSON Schema. Это тест на mock-сервере, не живое подтверждение подписочного маршрута IAM/gpt-6-luna. Фактическое принятие этой схемы выбранным исполнителем устанавливается только предзарегистрированными живыми ячейками; отдельный дополнительный пробный вызов не делается и бюджет не расширяется.
