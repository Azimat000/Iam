# Проверка безопасности S23

Проверены изменения `cbe39a0..175d6d6` в отношениях, реестре возможностей и мосте к создателю. Основанием служат проверка кода, воспроизведение на SQLite с тестовым Telegram и отдельное независимое ревью. Изменения затрагивают права и внешнюю отправку. Окончательное решение по предыдущим замечаниям — PASS.

| Находка в первой версии | Исправление | Проверка |
| --- | --- | --- |
| При лимите в одну отправку просьба и обычное сообщение из одного ответа могли уйти оба | Квота проверяется перед исполнением и учитывает начатые попытки обоих видов | `test_shared_quota_with_request_then_message` и `test_shared_quota_with_message_then_request` |
| При прерывании разрешённого повтора до отправки терялась ссылка на первую просьбу | Новый разбор сохраняет связь при незавершённом принятии | `test_authorized_repeat_survives_interruption_before_sending` |
| Ответ не сохранялся как связанное событие после чтения | Создаётся `creator.reply` со ссылками на исходную просьбу и прочитанное входящее из того же чата | `test_refusal_scenario_records_linked_reply_and_keeps_waiting_intention` |
| Сырой переход или другое входящее с тем же идентификатором могли выдать непрочитанный текст | Событие зарезервировано для контроллера. Он сверяет реальные события, порядок записи и входящее сообщение из почтового ящика. Проекция отдельно проверяет ссылку на чтение | В тесте отказа отклонены поддельный переход, подменённое событие и дубликат идентификатора. При сбое записи откатывается само чтение |
| Для Telegram показывалась настройка длительности, которую отправка не применяла | На странице Telegram доступны квоты отправок. Проверка заявленной длительности осталась у действий мира | `test_invalid_limit_or_denied_transition_leaves_settings_unchanged` |

Критические границы в базе `cbe39a0` находились в контроллере, защитных проверках панели и белом списке Telegram. Их проверили отдельно по истории изменений. Сохранённые права можно менять через три операции панели. Они сходятся в `Runtime.mutate`, затем проходят проверку причины, актуальной версии состояния и специального вмешательства контроллера. Ограничение отправки используют два потребителя, обычное действие и мост к создателю. Связывание ответа имеет один рабочий вход через подтверждённое чтение и одну проекцию для панели.

Независимый проверяющий воспроизвёл два сбоя на первой версии и попытку подмены уже после первой коррекции. На `175d6d6` повторил подмену с сохранённым псевдонимом перед настоящим сообщением. Контроллер отклонил её, текст в списке ответов не появился. Не осталось открытых замечаний по этим проверкам. Тесты обращались к имитации Telegram, живой канал остаётся отдельной проверкой S27.
