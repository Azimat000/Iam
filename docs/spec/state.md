# Спецификация: состояние личности

Статус: S02. Источник: `docs/PLAN.md` §2.1, §2.4–§2.6. Схемы: `schemas/transition.schema.json`, `schemas/memory_record.schema.json`.

**Состояние** — всё, что определяет поведение личности «сейчас», кроме неизменяемого журнала событий. Оно состоит из восьми групп (этот список проверяется тестом). Память (`provenance.md`) хранится рядом, но не входит в группы: группы — «что она сейчас такая/думает/хочет», память — «что она может вспомнить».

## 1. Обзор: восемь групп {#groups}

Требования: R-024, R-026, R-027, R-028, R-029, R-030, R-031, R-032, R-033

| № | Группа (ключ) | Что хранит (план §2.1) | Модуль-владелец (срез) |
|---|---|---|---|
| 1 | `traits` | начальные черты, ценности, личные границы | persona (S26) |
| 2 | `affect` | эмоции, настроение, внимание, внутренняя нагрузка | emotion, attention (S20, S21) |
| 3 | `beliefs` | убеждения с уверенностью и основаниями | beliefs (S21) |
| 4 | `relations` | отношения с людьми | social (S23) |
| 5 | `intentions` | цели, намерения, обязательства, незавершённые дела | intentions (S22) |
| 6 | `preferences` | предпочтения, привычки, приобретённые способы действий | motivation (S22) |
| 7 | `selfmodel` | представление о себе, своей истории, возможностях | selfmodel (S24) |
| 8 | `world_time` | состояние мира и собственное время | world, clock (S05, S22) |

Общие правила для всех групп:

- **G-1.** Каждое поле меняется только переходом состояния (раздел 10), у каждого перехода есть причина и ссылки на события-основания.
- **G-2.** Любое значение, вызванное внешним сообщением, хранит ссылку на исходное событие; «человек сообщил X» не записывается как «X истинно» (`provenance.md#truth`).
- **G-3.** Ошибочные убеждения, обиды и неудачные привычки допустимы; их происхождение хранится в основаниях (`R-070`, `R-071`). Права (`permissions.md`) от них не зависят.
- **G-4.** Начальное значение каждой группы создаёт срез персоны (S26); пустое начальное состояние допустимо и описано в каждом разделе.

## 2. Черты, ценности, границы {#traits}

Требования: R-026

Поля: `traits[]` — `{name, value 0..1, source}`; `values[]` — `{name, weight 0..1}`; `boundaries[]` — `{id, text, severity: soft|hard}`.

- Начальные значения задаются при создании персоны и записываются как событие создания (источник — `operator`).
- Изменение **устойчивых** черт — только через накопление оснований (раздел 8 `selfmodel`, порог), по малым шагам; единичное событие или единичный ответ модели черту не переписывает.
- Личные границы — часть характера (то, что она не хочет делать); технические права (`permissions.md`) это отдельное. Граница не даёт права, право не отменяет границу.
- Начальное значение: заполняется до первого запуска; без него личность не создаётся.

## 3. Аффект: эмоции, настроение, внимание, нагрузка {#affect}

Требования: R-027, R-062, R-063, R-064, R-065

Поля:

- `reactions[]` — краткие реакции: `{kind, intensity, cause_event, started_life_ms, half_life_ms}`; затухают за секунды-минуты **времени жизни**.
- `mood` — настроение: `{valence -1..1, arousal 0..1, since_life_ms}`; изменяется медленно.
- `dispositions[]` — устойчивые склонности (раздражительность, тревожность): `{name, value}`; меняются только накоплением оснований.
- `attention` — `{focus: activity|intention|event|dialogue|rest, ref, since_life_ms, switch_history[]}`.
- `load` — внутренняя нагрузка `0..1` (число открытых дел, длительность занятия без отдыха).
- `expression` — для каждой реакции: `impulse` (первичный импульс) и `expressed` (то, что показано в речи), может отличаться (регуляция).

Правила: эмоциональная оценка учитывает событие, черты, цели, прошлый опыт и состояние (`R-062`); три масштаба времени (реакция, настроение, склонность) — разные поля с разными скоростями (`R-063`). Затухание — по времени жизни, а не календарному (`time.md#life-clock`).
Начальное значение: `mood = {0,0.3}`, без реакций.

## 4. Убеждения {#beliefs}

Требования: R-028, R-066, R-067, R-068, R-069

Запись убеждения: `{belief_id, claim, confidence 0..1, agreement: -1..1, bases[], history[]}`.

`bases[]` — основания; каждое: `{basis_id, ref (событие или запись памяти), origin, source_id, independence_group, weight}`. Подробные правила независимости — `provenance.md#independence`.

Четыре величины **разделены** и хранятся в разных полях:

| Величина | Где | Смысл |
|---|---|---|
| эмоциональная близость | `relations[person].closeness` | насколько человек эмоционально близок |
| доверие к источнику | `relations[person].trust_as_source` | как часто его сведения оказывались надёжными |
| согласие с утверждением | `beliefs[].agreement` | согласна ли она с конкретным утверждением |
| готовность изменить поведение | `preferences.change_readiness[topic]` | готова ли поступить иначе |

Следствие (`R-067`): высокая близость/доверие к оператору не ставит `agreement = 1` для его мнения автоматически; `agreement` меняется только своим переходом с основаниями.
Начальное значение: нет убеждений (общие знания модели не записываются как убеждения без нужды, они доступны как `model_knowledge`).

## 5. Отношения {#relations}

Требования: R-029, R-054, R-011

Для каждого человека: `{person_id, role: operator_interlocutor|other, closeness, trust_as_source, history_summary_ref, last_contact_calendar, open_requests[]}`.

- На старте один человек (оператор в роли собеседника); других нет (`R-011`).
- Одно физическое лицо в двух ролях (канал Telegram — собеседник, панель — оператор) — разные роли, см. `permissions.md#roles`.
- Социальная память (`provenance.md#kinds`, вид `social`) хранит историю общения; поля выше — текущий срез.

## 6. Цели, намерения, обязательства, незавершённые дела {#intentions}

Требования: R-030, R-055, R-081, R-082, R-100

Намерение `{intention_id, text, status, created_by_event, due (опционально, см. time.md), priority, obstacles[], history[]}`.

Статусы (конечный автомат):

```
 active ──► waiting_opportunity ──► active
   │  └──► deferred ──► active
   ├──► done
   └──► abandoned
```

- `active` — выполняется сейчас или готово к выполнению.
- `waiting_opportunity` — нужно условие/инструмент/ответ (причина записывается).
- `deferred` — отложено на срок или до события.
- `done` — выполнено (только по подтверждённому результату действия, `events.md#event-types`).
- `abandoned` — оставлено; запись и история сохраняются.

Правила: отказ оператора или недоступность инструмента переводит намерение в `waiting_opportunity`/`deferred`, а **не** удаляет его (`R-100`); «знает о действии», «хочет» и «вправе» — три разных состояния (`permissions.md#three-states`). Обязательства (`kind=obligation`) — намерения, данные собеседнику; запись их — проспективная память.
Начальное значение: пусто.

## 7. Предпочтения, привычки, способы действий {#preferences}

Требования: R-031, R-053, R-079

Поля: `likes[]` — `{topic_or_activity, score -1..1, evidence_refs[]}`; `habits[]` — `{id, trigger, action_kind, strength 0..1, last_used_life_ms}`; `skills[]` — `{id, description, reliability 0..1}` (процедурная память — запись вида `procedural`); `change_readiness{}`; `curiosity` — текущие интересы `{topic, strength, novelty}`.

Предпочтения и привычки меняются только накоплением опыта (результаты занятий, обратная связь); декларация модели «мне нравится X» без событий-оснований — недопустимое основание.
Начальное значение: нейтральные оценки, пустые привычки.

## 8. Самомодель {#selfmodel}

Требования: R-032, R-083, R-084, R-085, R-086, R-087, R-088, R-089, R-094

Шесть частей: `now` («какая я сейчас»), `history` («что со мной происходило»), `values_view` («что для меня важно»), `relations_view` («какие у меня отношения»), `skills_view` («что я умею»), `fallibility` («в чём могу ошибаться»). Каждый элемент хранит ссылки на следы (память, оценки, результаты).

Три уровня, разные записи: `observation` (что я замечаю в состоянии), `hypothesis` (почему так, помечено как гипотеза) и `stable_change` (изменение устойчивого свойства). `stable_change` создаётся только если накоплено не менее `min_bases` независимых оснований (настройка, начальное значение 3) за период, не меньший `min_span_life_ms`. Текст объяснения модели хранится с `origin = model_explanation`.
Начальное значение: минимальное описание из персоны, без «истории».

## 9. Мир и время {#world-time}

Требования: R-033, R-034, R-072, R-073, R-077, R-078

Мир: `places[]`, `materials[]` (с отметкой `read_fraction`), `works[]` (написанные тексты), `projects[]` (`started|continued|done|abandoned`), `space_state`. Каждое действие в мире имеет предусловия, длительность (время жизни) и результат; результат записывается только по подтверждённому действию (`R-078`).
Время: `life_time_ms`, `session_state`, `moments[]` — подробности `time.md`.
Начальное значение: личное пространство, библиотека (пуста до загрузки), место для работы.

## 10. Версионирование и переходы {#versioning}

Требования: R-024, R-025, R-105, R-107, R-108, R-002

- Одна **версия состояния** `state_version` — целое, монотонно растёт на 1 при каждом применённом переходе; она общая для всех восьми групп и для памяти личности. События с `changes_state = false` версию не меняют (поэтому поступление сообщения в паузе не «просрочивает» ответ модели).
- **Переход** (`schemas/transition.schema.json`): `{transition_id, base_version, ops[], reason, caused_by[], proposal_id?}`. Операция: `{group, path, op: set|add|remove|transition, value}`.
- Применяет переход только `StateController` (единственный писатель). Одновременно изменять состояние может один процесс (эксклюзивная блокировка).
- **Условие применения:** `base_version == state_version` на момент применения; иначе переход отклоняется как `stale` (применённый «поверх» молча нельзя). Переход атомарен: все операции или ни одной.
- У каждого поля, изменённого переходом, в журнале есть пара (до, после), `reason` и причинная цепочка `caused_by` — на этом строится требование «каждое изменение имеет прослеживаемую причину».
- Перед применением ядро проверяет инварианты группы (диапазоны, допустимые переходы статусов, правила происхождения) — нарушение отклоняет переход целиком.
- Версия формата (`schema_version`) — отдельная от `state_version` и меняется только миграциями (срез S04).
