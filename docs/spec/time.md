# Спецификация: время

Статус: S02. Источник: `docs/PLAN.md` §1 (таблица: «Время»), §2.1, §5.1 («Пауза и перезапуск»). Реализация — `iam.clock.LifeClock` (S05).

Два времени, которые никогда не смешиваются: **календарное** (часы компьютера) и **время жизни** (собственные часы личности).

## 1. Календарное время {#calendar}

Требования: R-034, R-013

- Берётся с часов компьютера, хранится в UTC (`occurred_at`, ISO 8601, миллисекунды).
- Календарное время **не** используется для внутренних процессов личности (затухание, усталость, длительность занятий, забывание, сроки намерений по умолчанию).
- Календарное время используется для фактов внешнего мира: когда поступило сообщение, когда создана копия, когда прошла пауза. Личности оно доступно как данные (например, «сообщение пришло три дня назад»), но не как её собственный опыт ожидания.
- Календарное время может «прыгнуть» (смена часового пояса, ручная правка, синхронизация). Порядок событий поэтому определяется только `seq` (`events.md#ids`), а не календарём.

## 2. Время жизни {#life-clock}

Требования: R-013, R-034, R-182

`life_time_ms` — целое число миллисекунд жизни личности с момента создания.

- **Идёт только в состоянии сеанса `running`.** Пока сеанс `paused` или `stopped`, программа не запущена или упала — время жизни стоит.
- Измеряется **монотонными** часами процесса, а не календарными: скачок календаря не меняет время жизни. Формула в момент фиксации события: `life_time_ms = life_at_resume + (monotonic_now − monotonic_at_resume)`.
- Не убывает: у события с большим `seq` значение `life_time_ms` не меньше. Тест порядка — часть контрактных тестов S05.
- **Контрольная точка (heartbeat).** Пока сеанс идёт, ядро каждые `heartbeat_s` секунд (настройка, по умолчанию 5) записывает текущее время жизни. После аварийного завершения время жизни возобновляется с **последней записанной** точки; прошедшее после неё не засчитывается. Потеря — не больше `heartbeat_s`, всегда в сторону «жизни меньше», не больше.
- Ускоренные сценарии (тест-персонажи) могут использовать коэффициент `time_scale > 1`. Постоянная личность работает только с `time_scale = 1`; ускоренное время не переносится в постоянное хранилище (`R-165`).

## 3. Состояния сеанса и правила пауз {#sessions}

Требования: R-013, R-014, R-182, R-190, R-191, R-195, R-185

```
 stopped ──start──► running ──pause──► paused ──resume──► running
    ▲                  │                  │
    └───── stop ───────┴───── stop ───────┘
```

- Одновременно активен **один** сеанс (`R-190`); второй запуск отклоняется.
- Причины паузы (`reason`): `operator` (оператор), `technical` (лимит, потеря авторизации, повторяющийся сбой — `R-195`), `crash` (запись добавляется при следующем запуске), `session_limit` (30 минут или 10 обращений — `R-191`).
- В паузе: приёмник работает и сохраняет входящее (`input.arrived`), **модели не вызываются**, внимание не выбирает, занятия не продвигаются, намерения не меняются, новые события восприятия не создаются.
- Возобновление (`session.resumed`) записывает `paused_calendar_ms` (сколько календарного времени прошло) — как данные, не как переживание. Время жизни продолжается с прежнего значения.
- Перезапуск процесса эквивалентен паузе с причиной `crash` или `operator`; после него восстанавливаются мир, намерения и время жизни из последнего зафиксированного состояния (`R-182`). Незавершённое предложение или действие не считается выполненным (`events.md#event-types`).
- При остановке по лимиту или ошибке авторизации состояние сохраняется в том же виде (транзакция до остановки), в журнал пишется `system.limit_reached`/`system.error`, затем `session.paused` с причиной `technical`.

## 4. Плановые моменты {#moments}

Требования: R-036, R-081

Момент — запись `{moment_id, kind, due, owner_ref, fired_count}`.

- `kind = life`: срок в **времени жизни** (`due_life_ms`). Это обычный вид: окончание занятия, «вернуться к делу через час», срок намерения. Наступает только пока время жизни идёт; в паузе не наступает и не копится.
- `kind = calendar`: срок в календарном времени (`due_calendar`). Допустим только для фактов внешнего мира (например, договорённость с человеком на конкретную дату). Если календарный срок прошёл в паузе, **один раз** после возобновления создаётся `time.moment_due` с признаком `overdue_ms`; пропущенные повторения не проигрываются.
- Наступивший момент порождает событие `time.moment_due` (ключ `due:<moment_id>:<n>`) и запускает цикл. Фонового опроса нет.
- Момент не гарантирует действие: решает внимание (`events.md#perception-stages`, `state.md#affect`).

## 5. Что связано со временем жизни {#life-consumers}

Требования: R-019, R-063

Затухание реакций и настроения, ослабление доступности воспоминаний (забывание, срез S19), усталость и внутренняя нагрузка, длительность занятий в мире, пороги «накопленных оснований» для устойчивых изменений (`min_span_life_ms`) считаются по времени жизни. Пауза не «старит» память и не вызывает забывание.
