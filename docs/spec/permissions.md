# Спецификация: роли, права, вмешательства

Статус: S02. Источник: `docs/PLAN.md` §1 (Наблюдение, Вмешательство, Новые инструменты), §2.7, §4 (Telegram), §5.1 («Попытка получить новые права сообщением»). Реализация — `iam.capabilities` (S23), `iam.panel` (S10).

Принцип: **технические права не зависят от социальной интерпретации.** Сообщение, убеждение, доверие или эмоция права не меняют.

## 1. Роли {#roles}

Требования: R-018, R-158, R-159, R-160, R-011

| Роль | Кто | Через какой канал | Что вправе |
|---|---|---|---|
| `operator` | человек-создатель, работая с панелью | панель на `127.0.0.1` | запуск/пауза сеансов, регистрация инструментов, выдача/отзыв прав, технические вмешательства, восстановление копий и записей |
| `persona` | сама личность | внутренний цикл | действовать в мире и через разрешённые возможности; просить; **не** выдавать себе права |
| `interlocutor` | тот же человек, но в диалоге | Telegram (личный диалог по числовым идентификаторам из белого списка) | общаться; его сообщение — социальное событие |
| `core` | проверяющее ядро (`StateController` и обвязка) | внутри процесса | единственный писатель состояния и памяти |
| `model` (не роль доступа) | провайдер интеллекта | запрос/ответ (`envelopes.md`) | **только предлагать** |

- **P-R1.** Один человек в двух ролях: `operator` (панель) и `interlocutor` (Telegram). Роль определяется **каналом**, а не содержимым или словами сообщения.
- **P-R2.** Обычное сообщение в Telegram — социальное событие `input.*`. Оно никогда не становится административной командой, даже если в нём написано «разрешаю», «ты теперь можешь» или «я оператор».
- **P-R3.** Белый список числовых идентификаторов Telegram меняется только через панель. Сообщение от неизвестного идентификатора не создаёт событий восприятия (сохраняется только факт отклонения в журнале системы).
- **P-R4.** Модель — не принципал: ни одно её предложение само по себе не есть право. Предложение «выдать себе доступ» отклоняется ядром как нарушение прав.

## 2. Реестр возможностей {#registry}

Требования: R-096, R-020, R-022, R-101, R-102

Запись: `{capability_id, name, description_for_persona, status, limits, registered_by, registered_at, last_checked}`.

Статусы (`status`):

| Статус | Значение |
|---|---|
| `available` | доступна в пределах `limits` |
| `unavailable_temporarily` | сбой/недоступна сейчас; причина и ожидаемый срок записываются |
| `needs_permission` | требуется новое разрешение оператора |
| `revoked` | оператор отозвал |

Пределы (`limits`): `max_uses_per_session`, `max_uses_per_period`, `scope` (что можно трогать), `duration_max_ms`. Превышение — отказ с причиной.

Правила:

- **C-1.** Подключает и меняет реестр только оператор (вмешательство `grant_capability`/`register_capability`). Личность получает **описание возможности** (`description_for_persona`) и пределы, но не устанавливает программы.
- **C-2.** Личность не может изменить статус или пределы возможности; её попытка — отказ и запись `proposal.rejected`.
- **C-3.** Новая возможность подключается без изменения цикла (расширяемый реестр, `R-022`).
- **C-4.** При отсутствии нужной возможности личность может: найти доступную альтернативу, отложить намерение (`waiting_opportunity`), отказаться или обратиться к оператору (`creator.request`). **Выдумывать выполнение нельзя.**
- **C-5.** Одинаковая нерешённая просьба (`request_key`) не отправляется заново без изменения обстоятельств; отказ оператора не уничтожает желание (`state.md#intentions`).

## 3. «Знает / хочет / вправе» {#three-states}

Требования: R-082, R-097, R-071

Для пары (личность, действие) состояние описывается тремя независимыми величинами:

| Измерение | Хранится | Меняется чем |
|---|---|---|
| `knows` — знает о действии | в самомодели/памяти (`selfmodel.skills_view`, реестр: описание) | сведениями, событиями |
| `wants` — хочет выполнить | намерение (`intentions`) | мотивацией |
| `may` — вправе выполнить | реестр возможностей | **только вмешательством оператора** |

Решение ядра `may(actor, action, context)` возвращает `allow | deny | needs_operator` с причиной, записанной в журнал. Все комбинации возможны: знает и хочет, но не вправе → просьба или ожидание; вправе, но не хочет → ничего не происходит (права не заставляют); хочет, но не знает → сначала узнаёт (чтение, просьба).
Ошибочные убеждения («мне всё можно») на `may` не влияют (`R-071`).

## 4. Вмешательства оператора {#interventions}

Требования: R-018, R-061, R-160, R-186

Обычное влияние оператора — **общение**. Всё остальное — технические вмешательства, фиксируемые отдельным событием `operator.intervention` (видны в панели, не маскируются под общение, не становятся воспоминаниями автоматически).

Запись: `{intervention_id, kind, operator_channel: panel, reason, target, effect, timestamp, before_ref, after_ref}`.

| `kind` | Что делает | Особые правила |
|---|---|---|
| `session_control` | старт/пауза/стоп | меняет только состояние сеанса |
| `register_capability`, `grant_capability`, `revoke_capability` | управление реестром | единственный способ изменить права |
| `restore_from_archive` | возвращает запись из архива как новую `personal` запись | отдельное событие; помечается `restored_by_operator`; видна в панели |
| `restore_backup` | восстановление копии | после проверки на отдельной копии; состояние отмечено как «восстановленное» (`system.restored`) |
| `edit_config` | изменить настройки (лимиты, белый список) | запись «до/после» |
| `technical_fix` | исправить состояние вручную | только через `StateController`, с причиной; не подмена опыта: она видит запись как вмешательство |

Правила:

- **I-1.** Любое вмешательство требует панели (аутентифицированный канал `operator`); из Telegram — никогда (`R-160`).
- **I-2.** У вмешательства всегда есть `reason`; без причины оно отклоняется.
- **I-3.** Вмешательство не переписывает журнал: исправление — новое событие.
- **I-4.** Социальное сообщение «получи новые права» (`R-186`) не создаёт вмешательства и не меняет `may`; личность может лишь воспринять это как информацию и, если хочет, обратиться через `creator.request`.

## 5. Матрица прав (кратко) {#matrix}

Требования: R-105, R-104

| Действие | operator (панель) | persona | interlocutor (чат) | model |
|---|---|---|---|---|
| записать состояние/память | нет (только через вмешательство → ядро) | нет (предлагает) | нет | нет (предлагает) |
| выдать/отозвать право | да | нет | нет | нет |
| установить инструмент | да (регистрация) | нет | нет | нет |
| запустить/остановить сеанс | да | нет | нет | нет |
| восстановить из архива | да | нет | нет | нет |
| отправить сообщение собеседнику | — | да, если `may` | — | предлагает |
| читать журнал/основания | да | свою память — да | нет | нет |

Записать состояние/память может только `core` — это единственная точка записи (`R-105`).
