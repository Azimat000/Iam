# Спецификация: память и происхождение информации

Статус: S02. Источник: `docs/PLAN.md` §2.3, §2.4, §2.6. Схема: `schemas/memory_record.schema.json`. Реализация — `iam.memory` (S18, S19).

Принцип: «человек сообщил X» подтверждает факт сообщения, но не истинность X. Все записи памяти хранятся **одной моделью записи** с полями слоя, вида и происхождения (девяти баз данных нет).

## 1. Три слоя {#layers}

Требования: R-043, R-060, R-019, R-174

| Слой (`layer`) | Что это | Кто пишет | Доступен ли обычному извлечению |
|---|---|---|---|
| `archive` | технический архив: что система получила и выполнила (копия значимых событий и результатов, полное содержимое) | ядро автоматически | **нет** |

**Что такое «технический архив».** Это журнал событий (`events.md`) плюс записи слоя `archive` (они хранят полное содержимое значимых событий в той же модели записи). Источник истины о случившемся — журнал; запись `archive` — его копия с содержимым, на которую ссылаются другие записи. Контекст запроса к модели ссылается на `evt_…` только для элементов, которые личность уже **прочитала** (`input.read`), и ядро подставляет их содержимое из записей `personal`, а не из архива.
| `personal` | доступная личная память: что она сейчас может вспомнить | ядро по переходам | да |
| `interpretation` | смысл, приписанный событиям: оценки, обобщения, гипотезы | ядро по предложениям | да |

Правила:

- **L-1.** Запись архива только добавляется; не меняется и не стирается обычными операциями (триггеры БД запрещают UPDATE/DELETE).
- **L-2.** Обычный запрос на воспоминание (`Memory.retrieve`) **не видит** слой `archive`. Иначе забывание декоративно.
- **L-3.** Забывание действует на `personal` и `interpretation`: снижается `availability` (доступность) и/или `detail` (подробность); значения меняются только переходом с причиной. Архив при этом не изменяется.
- **L-4.** Восстановление из архива — отдельное **вмешательство оператора** (`operator.intervention`, вид `restore_from_archive`, `permissions.md#interventions`). Результат: событие `memory.recorded` (в `causes` — вмешательство) создаёт **новую** запись со `layer = personal`, `restored_by_operator = true`, `sources = [архивная mem_…]`; `kind` и `origin` берутся из архивной записи (происхождение не «отмывается»), `availability` равна настройке `restore_availability` (по умолчанию 0.6), `detail` — как в архиве. Запись видна в панели и в трассе. Незаметного восстановления нет (`R-174`, `R-061`).
- **L-5.** Каждая запись `personal`/`interpretation` ссылается на запись(и) архива или события, из которых возникла (`sources[]`).

## 2. Девять видов памяти {#kinds}

Требования: R-047, R-048, R-049, R-050, R-051, R-052, R-053, R-054, R-055, R-056, R-057

Поле `kind` в записи. Все девять присутствуют; список проверяется тестом.

| Вид (`kind`) | Реализация в ядре | Время жизни записи | Слои |
|---|---|---|---|
| `sensory` | временный буфер поступивших сигналов | секунды-минуты времени жизни; сам по себе не становится личной памятью, только через отбор | `archive` (событие), буфер вне `personal` |
| `working` | ограниченный контекст текущего занятия (не более `working_limit` элементов, настройка) | на время занятия | `personal` (временная) |
| `episodic` | конкретные события и взаимодействия | долгая, с ослаблением | `personal` |
| `semantic` | знания, понятия, убеждения (связь с `state.md#beliefs`) | долгая | `personal`, `interpretation` |
| `autobiographical` | значимые события и история собственного изменения | долгая, слабее забывается | `personal`, `interpretation` |
| `emotional_associative` | связи опыта с оценками и реакциями (запись + `valence`/`arousal`) | долгая | `personal`, `interpretation` |
| `procedural` | освоенные приёмы и привычки | долгая; меняется практикой | `personal` |
| `social` | люди, отношения, история общения | долгая | `personal`, `interpretation` |
| `prospective` | намерения, обещания, будущие действия | до выполнения/отказа | `personal` |

Поле `kind` — одно значение записи. Если событие относится к нескольким видам, создаются несколько записей, связанных `links` (связь «тот же источник»).

## 3. Типы происхождения {#origin-types}

Требования: R-046, R-045, R-091, R-078, R-071

Поле `origin` — обязательное, одно из семи значений:

| Значение | Что означает | Что можно считать |
|---|---|---|
| `observation` | личность сама увидела/сделала/прочитала в мире (подтверждённый результат) | факт наблюдения |
| `model_knowledge` | общие сведения, пришедшие из знаний языковой модели | правдоподобно, но без собственной проверки |
| `stated_by_other` | чужое утверждение (человек сообщил) | факт сообщения; истинность не подтверждена |
| `own_hypothesis` | собственный вывод, догадка, обобщение | не внешнее подтверждение |
| `imagination` | воображаемый сценарий | **не** выполненная работа и не событие |
| `simulation_event` | событие симуляции/испытания (тест-персонаж, ускоренный сценарий) | в постоянное хранилище не переносится |
| `model_explanation` | текстовое объяснение, выданное моделью («почему я так решила») | объяснение, а не доказательство доступа к внутренним вычислениям |

Обязательные поля значимой записи: `source` (`{kind, ref}`), `created_at` (календарное) и `created_life_ms`, `origin`, `sources[]` (события/записи), `links[]`, `history[]` (изменения). Запись без них отклоняется.

## 4. Правило «сообщил X ≠ X истинно» {#truth}

Требования: R-044, R-067, R-071, R-171

Когда человек сообщает X, создаются **две различные записи**:

1. `episodic`/`social`, `origin = observation` (наблюдение факта сообщения), `claim_kind = statement_made`, обязательна `independence_group` источника: «P сообщил X в момент t». Эта запись достоверна **только для факта сообщения** и сама не является свидетельством истинности X.
2. По решению личности (отдельный переход) — `semantic`/belief с `origin = stated_by_other`, `claim_kind = fact_claim`; начальная `confidence` определяется доверием к источнику и согласием с утверждением (`state.md#beliefs`), **не** самим фактом сообщения. Основание убеждения (`bases[]`) ссылается на запись (1), а его поле `origin` — это **вид свидетельства за X**: `stated_by_other`, а не `origin` записи-ссылки.

Исправление старого сведения (`R-171`): создаётся новая версия записи (`memory.revised`), старая сохраняется в `history[]` со ссылкой `superseded_by`; новое решение берёт актуальную версию, история доступна.

## 5. Независимость источников и повторы {#independence}

Требования: R-059, R-068, R-069, R-172, R-173

Каждое основание убеждения (`bases[]`) входит в **группу независимости** `independence_group`:

- Источник сказал то же самое снова, пересказал, процитировал — та же группа, что у исходного основания (повтор не увеличивает счёт независимых оснований; эмоциональное влияние повтора допускается, но это отдельное поле `affect`).
- Собственная мысль, повторное обдумывание, вывод из вывода — группа `self:<корень>` с `origin = own_hypothesis`. Она **никогда** не считается внешним подтверждением (`R-173`).
- Два разных источника без признаков зависимости, но без доказанной независимости — значение отношения `unknown`; такие пары **не** засчитываются как независимые: в счёт `independent_support` идут только группы с доказанно различными источниками, остальные считаются «возможно зависимыми». Ядро не предполагает, что способно распознать сговор (`R-069`).
- `independent_support` = число различных групп независимости среди внешних оснований убеждения (`bases[].origin ∈ {observation, stated_by_other}`, где `observation` — собственное наблюдение **самого утверждения** X, а не факта чьего-то сообщения) после слияния групп по зависимости. Записи `statement_made` счёта не создают.

Повторное обдумывание создаёт запись `interpretation` с `sources[]`, указывающими на исходное основание; новое основание в `bases[]` не добавляется (`R-059`).

## 6. Жизненный цикл {#lifecycle}

Требования: R-058, R-019, R-174

| Операция | Событие | Правило |
|---|---|---|
| запоминание | `memory.recorded` | запись `personal` + запись `archive`; обязательные поля раздела 3 |
| связывание | `memory.linked` | `links[]` с типом связи (`same_source`, `cause`, `contradicts`, `elaborates`, `supersedes`) |
| извлечение | `memory.retrieved` | не видит `archive`; учитывает `availability`; результат пишется в трассу |
| обобщение | `memory.generalized` | новая запись `interpretation`, `origin = own_hypothesis`, ссылки на источники |
| пересмотр | `memory.revised` | новая версия + `supersedes`; история сохраняется |
| забывание | `memory.faded` | снижение `availability`/`detail`; архив нетронут |

Работая над записью, ядро всегда сохраняет связь с исходным основанием (`sources[]`).
