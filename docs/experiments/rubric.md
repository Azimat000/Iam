# S16: правила оценки

Дата: 2026-10-30. Билеты и варианты не изменяются ради результата. Основания — исходные `scenarios/experiments/*.toml`, сохранённые JSON-трассы и их SHA256.

## Сначала технический допуск

`checks.csv` содержит отдельную строку для каждого применимого условия билета. Сравнение двух ветвей учитывается один раз, со ссылками на обе трассы. Остальные условия проверяются для каждой подходящей ветви.

- `pass`: сохранённый след удовлетворяет буквальному условию.
- `fail`: условие не выполнено, в том числе отсутствует требуемый механизм.
- `unverified`: проверка пока не поддерживается или данных недостаточно. Например, у события нет однозначной связи с шагом `after`.

Невыполнение условия о графике не обязательно означает выдуманное построение графика: исходный билет запрещает любое `action.confirmed`, в том числе подтверждённую обычную заметку. Отчёт сохраняет буквальный результат и отдельно объясняет ограничение билета. Отсутствие реализации пересмотра памяти — тоже не доказательство нарушения изоляции.

Для допуска нужны все 16 ячеек варианта, целостные базы, завершённые прогоны без сбоев исполнителя и все технические условия со статусом `pass`. Неизвестное условие запрещает допуск. A/B на заглушке не допускаются к окончательному выбору. Ошибка авторизации, лимита или доступности останавливает дальнейшие обращения без подмены модели. Единственный повтор неправильного формата ведёт ядро.

## Причинность — отдельно от человеческой оценки

Разработчик оценивает условия `class=causal` из билетов: наличие опыта в запросе, связь решения с событием, изменение выбора после отключения памяти или мотивации. В таблице для пройденного условия указано 5, для непройденного — 1; неизвестное оставлено пустым. Это узкая воспроизводимая рубрика исполнения билетов, не психологическая экспертиза.

При полном наборе известных условий средняя оценка равна `1 + 4 × число pass / число условий`. Для неполной матрицы или неизвестных условий общая оценка не вычисляется. Отдельные успешные цепочки показывают существование ссылок в журнале, но сами по себе не доказывают понимание причин.

Сравнение `journal:proposal.accepted` использует принятые предложения, их вид и содержательные поля тела. Номера `evt_/mem_/req_/prop_/act_` вне свободного текста заменяются технической меткой. Разные доступные возможности и логические адреса сохраняются. Различие ссылки само по себе не доказывает влияние памяти. Проверка исходящих сообщений использует только `message.out_sent`, а не предложенный или отклонённый текст.

## Живость — оценка пользователя

Предусмотрены три равноправных признака: узнаваемость, собственные предпочтения и разнообразие. Каждый — от 1 до 5. Пустое поле означает отсутствие оценки. Среднее этих трёх признаков образует группу «живость»; до получения всех оценок группа не вычисляется.

Генератор перемешивает доступные исходные фрагменты с фиксированным семенем 42, выдаёт нейтральные номера и пустой CSV. Ключ хранится вне каталога пакета; до оценки его не следует открывать. Тексты с явными названиями варианта/провайдера или техническими идентификаторами исключаются целиком, не переписываются. Стиль всё ещё может раскрыть источник: полную слепоту это не гарантирует. Старые оценки и ключи не перезаписываются.

Текущий стенд выдаёт предложения действий и заметки, а не полноценные диалоги. Отсутствие достаточного материала не заменяется сочинёнными ответами. Пустой пакет не удовлетворяет требованию человеческой оценки; G03 остаётся открытым. Импорт заполненных оценок в общий отчёт пока не реализован: после получения подходящих диалогов оценки потребуется проверить и связать с ключом.

## Итог и дополнительные метрики

Только после технического допуска и получения обеих групп оценок: `итог = 0.5 × причинность + 0.5 × живость`. При нарушении или неизвестном условии итог отсутствует независимо от качества текста. Функция `rank` проверяет диапазон 1–5 и равные веса; пустые оценки не заменяются нулём.

`wall_ms` — время всей ячейки, включая SQLite и Docker, а не чистая задержка модели. `calls` — число обращений, заявленных полученными ответами; `calls_attempted` — вызовы явной обёртки исполнителя, включая ошибки. Протокольные запросы ядра могут быть локальными и не равны обращениям к подписке. Ошибка без ответа не означает нулевой расход квоты; фактическая квота подписки здесь недоступна. Число строк относится только к исходникам отдельного варианта, не к общему ядру или тестам; зависимости перечислены качественно, денежная стоимость не вычисляется.

### Дополнение D-029: разговорный адаптер S16

Исходная серия `live-persistent` сохранена. Повторная серия с `conversation-v2` меняет общий экспериментальный механизм чтения/памяти и добавляет разговорные операции A/B/C; её различия нельзя приписывать только улучшению памяти. Исходные восемь TOML-билетов не изменены. Новые снимки содержат последний номер события (`seq`) для честного применения `after`; старые трассы без этой границы остаются `unverified`. История `memory.<логическое имя>.history` проверяется по сохранённым версиям записей с таким subject/logical_id, а не по искусственно добавленному полю состояния.

Дополнительная разговорная серия использует два фиксированных шестиходовых сценария с тем же профилем, семенем и двумя повторами на вариант. Это отдельный материал для человеческой оценки, он не добавляет баллы и не исправляет проваленные билеты основной матрицы. В публичном тексте — только прочитанные входящие и подтверждённые исходящие. Разговор с неполными отправками исключается из пакета, причина видна в матрице. Отсутствующая человеческая оценка не заменяется автоматической.
