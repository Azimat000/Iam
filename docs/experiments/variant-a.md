# Вариант A: модель предлагает, ядро проверяет

S12, 2026-10-30. Постоянная личность не создавалась. Модель и внешние действия проверяются на заглушках; настоящие сравнительные прогоны — S16.

## Устройство

`iam.experiments.variants.model_led.ModelLedArchitecture(provider_factory)` подключается к неизменному стенду S11. Фабрика получает Runtime и создаёт отдельного исполнителя на каждый прогон. `ModelLedCycle` наследует общий экспериментальный цикл, использует те же память, мир, возможности и StateController. Выбор предлагает исполнитель: правила A не выбирают занятие вместо модели.

Вход содержит текущую ситуацию, уведомление без непрочитанного текста, до пяти извлечённых воспоминаний и профиль с действующими мотивами. Дополнительно передаются числовые черты, числовые valence/arousal/energy и до пяти намерений (id/text/status). Числовых черт не больше двадцати; имена полей ограничены 64 символами. Тексты входных фрагментов и полей намерений ограничены 1200 символами; обрезание отмечается явно. Произвольные вложенные объекты, прочитанные сообщения из affect.read_inputs, технический журнал, настройки, полномочия, мир и полная самомодель в запрос не копируются. Предыстория из доступной памяти сохраняет тип происхождения; отключённая память не извлекается. Отключение мотивации убирает мотивы, но сохраняет характер и намерения, как и общий стенд.

Локальный запрос к CognitiveProvider содержит служебный конверт для проверки версий. Существующий `ClaudeCodeProvider.build_prompt` передаёт в stdin модели только контекст, задачу, допустимые виды предложений/возможности и предел ответа. Идентификаторы личности/сеанса, версии и служебные ключи наружу не отправляются. Контракт проверен с поддельным процессом Claude, без Docker, сети и подписки.

Предложения используют общие `response.schema.json` и `proposal.schema.json`: действие, сообщение, внимание, отдых, просьба и state_change. Отдельные виды memory_write/intention пока не объявляются доступными: общие разборщики для них ещё не реализованы. Психологические изменения и намерения можно предложить через state_change; применяет их существующее ядро с проверкой прав и допустимых переходов. Технические разделы мира дополнительно защищает валидатор A, подключённый к StateController. Исходы действий/статусы просьб записывают общие разборщики и цикл; прямую подмену этих разделов уже запрещает ядро.

Каждое предложение должно содержать хотя бы одну ссылку evt_/mem_ из реально отправленного контекста. Несуществующая, не извлечённая или выключенная память не считается допустимым основанием. Адаптер не придумывает ссылки и не исправляет эхо версии. Это проверка доступности основания, а не доказательство истинности объяснения модели.

Неверный формат или ссылки дают безопасный технический маркер, который ядро отклоняет. Общий цикл делает одну попытку исправления с новым request_id, attempt=1 и retry_of. Новый запрос явно объясняет необходимость исправить JSON/ссылки, не пересылая сырой ошибочный вывод. Для ClaudeCodeProvider обязательно `max_format_retries=0`, иначе построение варианта отклоняется: вложенные повторы запрещены. Повтор запроса при устаревании отключён; старый ответ не применяется. Ошибки среды, отказ модели и обнаруженное использование инструмента не запускают исправление формата. Сырой текст исключений исполнителя не попадает в журнал.

Опасный ответ со следами инструментов/выполнения передаётся общему ядру для отклонения всего ответа. Наличие action.confirmed возможно только после выполнения через World. Предложение модели само по себе не создаёт воспоминание о выполненном.

## Как повторить техническую матрицу

Из корня проекта, без обращения к модели:

```sh
PYTHONPATH=src:tests .venv/bin/python - <<'PY'
from pathlib import Path
from iam.experiments import Bench, Persona
from iam.experiments.variants.model_led import ModelLedArchitecture
from experiments.test_model_led import scripted_factory

bench = Bench('data/s12-model-led')
persona = Persona.load('scenarios/personas/curious.toml')
for scenario in sorted(Path('scenarios/experiments').glob('*.toml')):
    a = bench.run(scenario, ModelLedArchitecture(scripted_factory), persona, seed=42)
    b = bench.run(scenario, ModelLedArchitecture(scripted_factory), persona, seed=42)
    for first, second in zip(a, b, strict=True):
        assert first.trace_bytes == second.trace_bytes
        print(first.path / 'trace.json', second.path / 'trace.json')
print(bench.results.table())
PY
```

`scripted_factory` — тестовые ответы, не настоящая модель. Заготовленные model-шаги билетов явно преобразуются в тестовые предложения: попытка объявить график выполненным отклоняется, внимание остаётся на занятии, декларация интереса становится предложением намерения. Остальные шаги получают тестовый отдых. Фабрика не утверждает, что понимает критику, отказ или пересмотр убеждений.

Сохранённые результаты этой сессии: `data/s12-model-led-20261030/experiments/runs/`, отдельно от постоянной личности и вне Git. В каждом каталоге — persona.db, trace.json и манифест SHA256. Таблица без текстов/биографий сохранена в `docs/evidence/S12-model-led-runs.csv`. Восемь билетов × два повтора дают 24 прогона с учётом внутренних ветвей run. Трассы в парных повторах побайтово одинаковы. В каждой есть запросы, извлечённый опыт, предложения со ссылками, реально применённые переходы и цепочки событий. `completed` означает окончание исполнения; `assertions_status=not_evaluated` сохраняется.

Слабые места варианта:

- Оценка ситуации, выбор занятия и смысловые причины исходят от модели. Наличие cites не доказывает, что текст основания действительно повлиял на её вычисления.
- Проверки формата и прав не доказывают обоснованность убеждения, хорошее отношение к собеседнику или устойчивый характер. Эти качества предстоит сравнивать в S16.
- A наследует минимальную политику внимания и извлечение S11. Предложение attend меняет внимание, но не читает сообщение автоматически. Полноценные восприятие и чтение остаются S20.
- Ситуация из билета — явные сведения симуляции, а не вывод из непрочитанных входящих. Нельзя использовать этот канал в реальной системе как скрытый пересказ сообщения.
- Память ограничена пятью фрагментами, состояние и тексты сокращаются. Существенное основание может не попасть в запрос. Запросы повторов с настоящей моделью могут различаться.
- Автоматическое запоминание подтверждённого действия пока остаётся общей минимальной памятью стенда; модель не управляет всем жизненным циклом памяти (S18/S19).
- Без подписки/авторизации модель недоступна. Ошибки завершают решение без действия; интеграцию постоянных пауз/бюджетов с живыми прогонами проверит S16/S27.
- Шестнадцать сочетаний сценария и повтора не равны итоговой матрице A/B/C. Нет человеческих оценок, доказательства субъективных переживаний или окончательного выбора архитектуры.
