# Вариант B: правила выбирают, Codex формулирует текст

S13, 2026-10-30. Отдельный экспериментальный вариант на общем стенде S11; вариант A и постоянная личность не изменены. Рабочий исполнитель — существующий `CodexProvider`, модель `gpt-6-luna`, без смены модели и запасного API. Основная матрица проверена на заглушках; дополнительно выполнена одна живая операция Codex.

## Устройство

`iam.experiments.variants.hybrid.HybridArchitecture(provider_factory)` создаёт новый цикл для каждого прогона. Проверяющее ядро, часы, память, возможности и мир берутся из Runtime стенда без замены. Фабрика подключается явно; автоматических внешних запусков нет.

Внимание выбирается до модели. Оценки учитывают текущую энергию, любознательность, общительность и настойчивость, активные намерения, тип события и историю переключений. Уведомление даёт только факт поступления; его текст и число накопившихся уведомлений в оценке не используются. К прежнему фокусу добавляется инерция 0.12; отвлечение на уведомление уменьшается на 0.05 за переключение, не более чем на 0.3. При равенстве порядок фиксирован. Намерение выбирается по стабильному порядку идентификаторов. Часы берутся на момент обработки, а не из старой отметки события.

Динамика разделяет короткую реакцию, настроение и устойчивые склонности. Реакция затухает с масштабом две минуты жизни; уведомление добавляет 0.08, подтверждённое завершение занятия — 0.25. Настроение за событие проходит 8 % пути к реакции. Устойчивые склонности читаются из числовых черт и не переписываются. Это параметры кандидата для сравнения, не подтверждённая психологическая модель. Ход календарного времени во время паузы не заменяет время жизни.

Правила оценивают три действия: отдых, внимание к уведомлению и заметку. Заметка возможна при действующей мотивации и доступной возможности заметок. На её оценку влияют энергия, любознательность, настроение, количество извлечённых воспоминаний (вклад ограничен тремя) и фокус на намерении. Отдых становится привлекательнее при низкой энергии. Все признаки, оценки и выбранный максимум сохраняются в `affect.hybrid.decision` и стадии appraisal отчёта. Текстовое обоснование строит программа из этих чисел; explanation/rationale модели его не заменяют.

Динамику записывает StateController до запроса. Предложение ссылается на событие оценки, исходный повод и доступную память; через событие оценки прослеживается извлечение памяти. После принятого решения история согласуется с фактическим вниманием. Отдых прибавляет 0.12 энергии, подтверждённая заметка расходует 0.08. Ошибка/отказ модели и неподтверждённое действие не дают такого эффекта. Отказ ядра записать обратную связь виден как failed, даже если само действие уже подтверждено.

## Узкая операция модели

Только после выбора заметки вызывается CognitiveProvider с purpose=`summarize`. Ему разрешён ровно один `no_action`, body строго `{reason: текст}`, непустой текст до 1200 символов и непустые ссылки evt_/mem_ из переданного контекста. В схеме Codex тело передаётся строкой body_json. Здесь no_action — транспорт текста: исходное решение о занятии уже принято программой. Любое другое действие/изменение состояния или дополнительные поля отвергаются.

После проверки адаптер B берёт только текст. Программа формирует своё action для существующей возможности заметок, сохраняя исходное эхо версии/запроса для проверки ядром. Текст помечен model_explanation и не считается отдельным подтверждением фактов. Модель не задаёт capability, параметры прав, причины выбора, склонности или результат выполнения. Результат подтверждает общий экспериментальный World. Для уведомления программа использует attend, для отдыха — no_action; оба случая обходятся без модели.

Неверный формат/операция допускает одно исправление общим Cycle. У CodexProvider требуется `max_format_retries=0`, иначе построение B отклоняется. Второй неверный ответ завершает решение. Устаревшее эхо не исправляется и не пересчитывается. Отказы, признаки инструмента и ошибки среды не маскируются повтором. Класс ошибки сохраняется, сырой текст исключения в журнал не передаётся. При сбое текста модель не заменяется и заметка не объявляется сделанной.

Контекст содержит только явные фрагменты общего цикла: уведомление без тела, доступную память, ситуацию билета, профиль/мотивы и числовую запись уже сделанного выбора. Отдельные тексты ограничены 1200 символами с отметкой обрезания. Дамп мира, самомодель, прочитанные сообщения и произвольные поля traits/affect не пересылаются. Обычное извлечение не получает технический архив. Выключение памяти убирает её из контекста и оценок; выключение мотивации исключает заметку.

Внешний запрос модели сужен до allowed_proposals=[no_action], allowed_actions=[]. Служебный конверт для ядра допускает собственные action/no_action/attend программы. Фактически отправленный узкий запрос отдельно сохранён в report.stages[].detail.model_requests; конверт общего протокола остаётся в decision_trace.requests. Идентификаторы личности/сеанса, версия и служебные ключи исключаются из stdin существующим CodexProvider.build_prompt.

## Проверки и сохранённые результаты

Профильные проверки:

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/experiments -p test_hybrid.py -v
```

Повторить матрицу без модели:

```sh
PYTHONPATH=src:tests .venv/bin/python - <<'PY'
from pathlib import Path
from iam.experiments import Bench, Persona
from iam.experiments.variants.hybrid import HybridArchitecture
from iam.experiments.variants.model_led import ModelLedArchitecture
from experiments.test_hybrid import scripted_factory, metrics

bench = Bench('data/s13-repeat')
persona = Persona.load('scenarios/personas/curious.toml')
for path in sorted(Path('scenarios/experiments').glob('*.toml')):
    first = bench.run(path, HybridArchitecture(scripted_factory), persona, seed=42)
    second = bench.run(path, HybridArchitecture(scripted_factory), persona, seed=42)
    baseline = bench.run(path, ModelLedArchitecture(scripted_factory), persona, seed=42)
    for a, b, control in zip(first, second, baseline, strict=True):
        assert a.trace_bytes == b.trace_bytes
        calls_b = sum(metrics(d)['model_calls'] for d in a.trace['decision_trace'])
        calls_a = sum(len(d['requests']) for d in control.trace['decision_trace'])
        assert calls_b <= calls_a
print(bench.results.table())
PY
```

Восемь билетов × два повтора дают 24 прогона с внутренними ветвями. Сохранены отдельные persona.db, trace.json и манифесты SHA256 в `data/s13-hybrid-20261030/experiments/runs/`; контроль A — `data/s13-baseline-a-20261030`. Базы/тексты остаются локально вне Git. Таблица с метриками и хешами — `docs/evidence/S13-hybrid-runs.csv`.

В этой технической матрице B сделал **12 обращений**, A — **30** для того же числа повторов. Неравенство проверено для каждого прогона. Считаются попытки вызова CognitiveProvider.propose, включая неверный формат и ошибки; это консервативный счётчик обращений к исполнителю, не токены или стоимость. Локальные конверты правил имеют usage.calls=0 и не считаются модельными вызовами. Проверка сравнения использует валидные для обеих архитектур заглушки; она не обещает такое же соотношение на произвольных живых ответах и дополнительных исправлениях. Расход подписки и скорость настоящих сравнений измерит S16.

Живая проверка — `docs/evidence/S13-hybrid-live.json`: программа выбрала note, настоящий Codex GPT-6-Luna за одно обращение вернул текст, ядро приняло action, экспериментальный мир подтвердил его. verify и проверка целостности SQLite прошли; внешний auth не изменился. Полная трасса сохранена локально по пути в отчёте и проверена на значения токенов сканером без вывода секретов. Это реальная модель и симулируемый мир, без Telegram и постоянной личности.

## Слабые места и границы приёмки

- Правила чисел пока заданы вручную; предстоит проверить, не получается ли однообразное поведение. Большая часть текста профиля ещё не используется в оценках, конкретные мотивы влияют пока только своим наличием.
- Механизм различает типы событий, но не понимает смысл тёплого и холодного опыта. Количество доступных воспоминаний влияет на оценки; различие их эмоционального смысла пока не влияет. Не заявляется успешность смысловых проверок исправления даты, критики, отказа или нового интереса.
- Уведомление можно заметить, но этот кандидат не читает его автоматически и не отвечает в Telegram. Ситуация билета — явные сведения симуляции, её нельзя превращать в скрытый пересказ непрочитанного.
- Инерция ограничена видом фокуса; накопленный счётчик переключений не забывается. При нескольких намерениях нет содержательной оценки их срочности. Полные механизмы — будущие S20–S22.
- Текст модели проверяется по форме, длине и доступным ссылкам; достоверность и качество текста этим не доказаны. Нет автоматического принятия новых убеждений/интересов из summary.
- Мир S11 подтверждает симуляцию заметки. Полная библиотека, чтение глав, настоящие проекты и жизненный цикл памяти остаются будущими срезами.
- `completed` означает завершение исполнения; во всех матричных трассах сохраняется `assertions_status=not_evaluated`. Нет слепых человеческих оценок, выбора архитектуры или доказательства субъективных переживаний.
- Живая операция проверяет подключение Luna к B; полная живая матрица A/B/C, нагрузка и оценки пользователя остаются S16/G03. G02/G09 остаются открытыми и не блокируют S13.

Отдельное read-only ревью обнаружило и помогло исправить превращение уведомления в отдых, использование устаревшего времени события и игнорирование отказа обратной связи. Для каждого случая добавлены проверки. Основной агент самостоятельно запустил профильные и общие проверки и прочитал фактические изменения; окончательные числа и замер покрытия зафиксированы в итоге S13 и `docs/evidence/S13-coverage.txt`.
