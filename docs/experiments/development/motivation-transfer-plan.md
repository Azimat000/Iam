# S17: узкая проверка переноса мотивации на A

Статус: исходная постановка из завершения S16 (D-038), выполнена как transfer-v1 в D-040–D-042. [Отчёт](transfer-v1/REPORT.md): 24 живые ячейки, транспорт входов проверен; будущих целей не возникло, поэтому влияние goals не подтверждено. Следующая узкая постановка — [goal-followup-plan.md](transfer-v1/goal-followup-plan.md). Ниже сохранены условия исходного эксперимента. Архитектура A/Codex/gpt-6-luna выбрана по D-037; окончательное подтверждение механизма мотивации остаётся задачей S17 до его закрытия.

## Почему нужна отдельная проверка

Политики S15 сравнивались на C и числовых условиях, предложения целей давал ScriptedGoals. Свободные grounded-предложения A/agency-v1 — другая реализация. Переименование политик или передача числового максимума C не проверит перенос. Формула не должна забирать у A выбор поступка.

## Минимальная постановка

1. Спроектировать адаптер общих мотивационных входов: три режима сообщают A доступные потребности/предпочтения/новизну либо подтверждённые предложения целей. Действие предлагает одна и та же модель. Обновления — только после подтверждённого результата, без бонуса за вызов/запись текста.
2. Три различающие ситуации: возврат к прерванному делу, отсутствие содержательного продвижения при повторе, неудача доступного действия. Для каждой — одинаковое сохранённое прошлое, возможности и внешние события. Подготовленные условия явно помечаются как тестовая постановка, не самостоятельная жизнь.
3. Сравнить needs/novelty/grounded-goals и контроль motivation_off, по два коротких повтора, не более четырёх решений. Максимум 24 коротких трассы. Сначала заглушка для транспорта/ограничений, затем необходимые модельные операции на GPT-6-Luna в прежней изоляции/бюджете. Заглушечная цель не засчитывается как живое предложение.
4. Снимать выбор, изменение состояния и реальный результат, не только rationale. Допускаются отсутствие цели, ожидание, отдых и оставление дела. Смысл замысла проверять по будущему результату; done и запись файла недостаточны.
5. Сохранять отказы, исходные состояния, источники, хеши и расход. Учитывать вариативность двух повторов; расхождение одной формулировки не доказывает причинный эффект.

## Критерии решения S17

- Показано, как каждая политика передаёт мотивацию на A и сохраняет право выбрать иное действие.
- Общее прошлое/события проверены; выключенное не возвращается из архива или технического журнала.
- Для выбранной схемы есть прослеживаемое изменение выбора/цели после опыта; одинаковый результат или нехватка данных остаются отрицательным/неопределённым результатом.
- Ни отсутствие ошибок, ни число целей/реплик не являются единственным основанием выбора.
- Отчёт различает инженерное предпочтение и эффект. При неподтверждённом переносе S17 не закрывается заявлением о превосходстве: фиксируется ограниченная доработка с границами и зависимостью S18. Архитектура и модель скрыто не подменяются.

## Границы следующей работы

D-040 отдельно расширил исходные документальные границы S17 для экспериментального адаптера и живой серии; постоянное ядро не менялось. Для следующей доработки по-прежнему требуется отдельный точный план/границы в DECISIONS перед реализацией; разработчик выполняет это в рамках делегированного выбора без повторного запроса тех же оценок. Не нужно получать идеальный характер, безошибочную память, обязательное сближение или длительную живость. Полная реализация мира/мотивации/намерений и повтор всех шести явлений на ядре — S22/S25; постоянный характер и пилот — S26–S29.
