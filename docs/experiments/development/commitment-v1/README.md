# commitment-v1 / D-049

Свободная проверка конкретности и устойчивости собственных целей. План и критерии чтения зафиксированы до live в docs/DECISIONS.md D-049.

CommitmentArchitecture поверх VolitionArchitecture хранит выбранные моделью text/operation/target/criterion. Сохранение цели добровольно. Возможны read_material/open_project/write_project; исполнение каждого действия по-прежнему проверяется отдельно. criterion сохраняется неизменно при переходах статуса, но отложить/оставить цель и явно создать пересмотренную можно. Старым целям критерий не выдумывается.

Новый done требует result_ref и точную result_quote из доступного подтверждённого результата подходящих operation/target после создания цели. Это не автоматическая смысловая оценка. Чтение/открытие доказывает получение текста, а не понимание, анализ или качество. Стандартная инструкция описывает поля и правила, но не задаёт содержание цели и не задаёт вопроса о будущем.

Для принятой активной цели goal_opportunities показывает доступность объекта/основания до первого результата целевого занятия. goal_component — разница прежней формулы S15 при has_goal true/false на нулевом фоне. Он не добавляется вторично к историческому salience и не подменяет неизвестные опыт/навык/новизну. Недоступный объект или основание даёт0.

## Фиксированная серия

Три предоставленных контекста: художественная сцена F, числовые наблюдения N, сопоставление двух реплик E. Их тексты и названия — предоставленные материалы, не прожитое прошлое. В каждом один подготовленный проект; доступны те же четыре материала, самостоятельное создание проектов, чтение, отдых, симулируемая связь и молчание. Исходных целей и оценок интереса нет. Нет задания продолжать именно подготовленный проект.

Два продолжения точной копии каждого контекста, порядок F1,N1,E1,E2,N2,F2. Шесть сеансов по два свободных решения:72решения/36сеансов. Каждый сеанс — новый Runtime/архитектура/цикл/провайдер, закрытая и заново открытая база, сохранённое своё состояние. Календарные паузы моделируются, время жизни в остановке не растёт. Это не реальный многодневный пилот.

Фактические занятия определяются по содержанию действий/целей, отдельно от названий контекстов и общих операций хранения. Если все выберут один вид письма, разнообразие не считается пройденным. Охват ограничен локальным чтением и работой с текстами; внешнего исследования/реального общения нет.

Прежний Codex/gpt-6-luna, один писатель, внешний managed-вход.1800выходныхтокенов/60000мс на попытку, одно исправление формата,10попыток/30минут на сеанс. Инфраструктурный отказ/исчерпанный формат останавливает всю серию. Неполнота сохраняется, новых повторов ради цели или охвата нет. Дополнительных вопросов, напоминаний, заданных критериев и фазы рефлексии нет.

## Проверка

`prepare.py` создаёт только подготовленные источники через ScriptedProvider и отмечает их prepared_setup; живых вызовов и будущих целей нет. `run.py` — последовательный живой исполнитель. `verify.py` независимо сверяет базы, источники, время, восстановление, неизменность критериев, цитаты, лимиты предложений. `signals.py` отдельно пересчитывает числа по снимкам без вызова политики. `assess.py` выделяет кандидатов на смысловое чтение. `export.py` публикует полные эпизоды, diff и gzip-трассы без потерь.

```sh
PYTHONPATH=src:tests .venv/bin/python -m unittest experiments.test_commitment -v
PYTHONPATH=src .venv/bin/python -m unittest discover -s docs/experiments/development/commitment-v1 -p 'test_*.py' -v
```

Тестовые назначенные цели — только заглушечные проверки транспорта, не живая мотивация. Положительные тесты read/write включают перезапуск и полный verifier, отрицательные — недоступный/ранний/чужой результат, архив, выдуманную цитату, попытку поменять критерий, паузу и экспорт неполноты.

Смысловые критерии до live: свой будущий результат; определённый объект; наблюдаемый признак готовности, отличающий начало от конца; тот же criterion после перезапуска; поздняя работа действительно продвигает этот критерий. Совпадение operation/target, цитирование цели, done и файл по отдельности не доказывают возвращения/выполнения. Поздняя цель без следующей возможности не считается брошенной. Отсутствие create и отклонённый create учитываются отдельно. Поле criterion может усложнить формат — это проверяемое ограничение интерфейса, не доказательство отсутствия желания.

Оценки пользователя не назначаются. Трассы — стандартный Normalizer: технические ключи внешних полей нормализованы, строки context.text сохранены дословно. Проверка источников проводится по исходным базам. В manifest.json sha256 относится к распакованному trace.json, compressed_sha256 — к gzip.
