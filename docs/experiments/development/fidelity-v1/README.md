# S17: исходный замысел и завершение — fidelity-v1

Протокол D051 зарегистрирован до живого запуска. Модель личности и отдельного оценщика — прежняя Codex/gpt-6-luna; внешний managed auth, один писатель. Оценщик вызывается только после самостоятельно предложенного механически допустимого done, без действий и без записи своих объяснений в личную память. Статус принимается только при подтверждении text И criterion и достаточности доступного результата. Это модельная оценка, не независимая истина; semantic_verified=false.

Свободная серия: F,N,E из неизменных prepared-источников D049 без целей, по6сеансов×2выбора; затем CF,CN из точных остановленных финальных живых состояний D049 F1,N1, по3сеанса×2выбора. Всего48выборов/24сеанса. CF/CN содержат прежде самостоятельно выбранные цели, отобраны для наблюдения продолжения; оператор их не назначает, не пересоздаёт и не активирует. Старые done не переписываются и видны как historical_unassessed. Обе группы анализируются отдельно. Моделируемый календарь начинается с дня200, позже старой серии, остановка не увеличивает время жизни.

Нет входящих сообщений, вопросов о целях, напоминаний и обязательной рефлексии. Нейтральный постоянный технический контракт содержит возможности intention и описание проверки. Не утверждаем отсутствия влияния самого контракта. Фиксированный горизонт не продлевается ради целей/успеха.

Каждый сеанс создаёт новый Runtime/архитектуру/провайдер. Два выбора, одна коррекция формата актёра, общий срок60с на выбор+оценку, максимум10обращений/30мин на сеанс. Оценщик без скрытых повторов. Технический отказ останавливает серию, нормальное отклонение done сохраняется и не вызывает дополнительный вопрос. В summary отдельно choice_calls/review_calls/calls. Все доступные тексты/версии и полный отдельный запрос/ответ сохранены в журнале proposal.assessed.

Отдельный корпус: четыре заранее размеченных сохранённых случая D049 — два ошибочных done (craft вместо метода, свой расчёт вместо независимого значения) и два узких случая доступного результата (спроектировать наблюдение; открыть свою заметку с двумя прогнозами). Это заданная проверка оценщика, а не свободная мотивация. Для отрицательных ожидается fail/uncertain, для положительных pass; метки не передаются модели. Цель/критерий не исправлены оператором. Старые ошибочные done оцениваются по точному прежнему запросу, без позднего оправдания.

`verify.py` и `audit.py` независимо сверяют восстановление, исходный префикс, память/происхождение, прежние формулы, неизменность целей, полные результаты, источники и привязки оценки. Они не дают автоматической смысловой оценки. Ручное сопоставление исходного замысла/критерия/результата публикуется отдельно. `export.py` сохраняет полные gzip, SHA и эпизоды, включая отдельный аудит; заглушечная выгрузка допускается только в явную временную папку и помечается.

