# S03 — Каталог сценариев проверок

**Этап:** 1 (Спецификация) · **Зависит от:** S02 · **Требования:** все проверки из плана §3 и §5

## Простыми словами
Записываем «экзаменационные билеты» заранее, до кода: 19 обязательных проверок (например, «непрочитанное сообщение не влияет на ответ»), 8 сценариев для сравнения вариантов интеллекта и 6 проверок мотивации (интерес, возврат к незавершённому, потеря интереса, неудача, переключение, возможность ничего не делать). Каждый билет — файл с входными событиями, ожидаемым результатом и признаком провала, написанный так, чтобы любой вариант системы можно было прогнать одинаково.

## Что делаем
- `docs/spec/scenario-format.md`: формат сценария (предыстория, входные события по шагам, наблюдаемые утверждения о журнале и состоянии, переключатели «память выкл / мотивация выкл», связанные требования).
- `scenarios/required/*.toml` — 19 сценариев из §5 плана; `scenarios/experiments/*.toml` — 8 сценариев для сравнения вариантов (покрывают разный опыт, исправление, повтор критики, непрочитанное, отсутствие сообщений, новый интерес, нет инструмента, отказ); `scenarios/motivation/*.toml` — 6 проверок мотивации.
- `tools/scenarios.py`: `validate` (формат, ссылки на требования), `list`, `coverage` (какие требования закрыты сценариями).
- Дополнить `check` в requirements.toml ссылками на ID сценариев.

## Границы файлов
Можно: `scenarios/**`, `docs/spec/scenario-format.md`, `tools/scenarios.py`, `tests/test_scenarios.py`, `requirements.toml` (check), файл среза.
Нельзя: `src/**`.

## Проверки
- Каждая из 19 строк таблицы §5 плана есть ровно в одном сценарии.
- Каждый сценарий ссылается на ≥1 существующее требование; каждое требование kind=functional имеет сценарий или тест.
- `scenarios.py validate` и `reqs.py validate` зелёные; тесты валидатора на сломанных образцах.
- Утверждения сценариев формулируются через наблюдаемое (журнал, состояние), а не через «модель должна думать».

Каталог из 33 сценариев: `scenarios/required/` — 19 (по одной на строку таблицы §5.1, тексты строки дословно), `scenarios/experiments/` — 8 (план §3.2), `scenarios/motivation/` — 6 (план §3.3, у каждого метрика). Инструмент `tools/scenarios.py` (`validate`, `list`, `coverage`). Поле `check` у 75 требований дополнено путями к сценариям (двусторонняя связь проверяется); остальные поля реестра не менялись, статусы не повышались. Решение D-010 в `docs/DECISIONS.md`.

**Как проверено.** `python3 -m unittest discover -s tests` — 155 тестов зелёные (в т. ч. `tests/test_scenarios.py`: 53 теста на сломанных образцах каждого правила, на временном корне репозитория, в-процессном и подпроцессном запуске команд, на реальном каталоге: все 19 строк плана ровно по одному разу, 4 решения на прогон, утверждения «строки нет» не вакуумны). `scenarios.py validate`, `reqs.py validate`, `reqs.py coverage --check`, `memory.py check` зелёные. Охват строк `tools/scenarios.py` измерен стандартным `trace` (внешнего измерителя ещё нет): 471 из 472 операторов, не исполнена только строка `sys.exit(main())` (её исполняет тест подпроцессом); ветви отдельно не измерялись. Независимое ревью подагентом нашло 8 серьёзных и около 20 средних замечаний (вакуумные утверждения, противоречия `time.md`/`envelopes.md`, лишнее условие «решения различаются»); исправлены, форма проверок усилена (привязка ссылок на шаги к прогону, неповторяемость, непустота).

**Не сделано / ограничения.** Сценарии ничего не исполняют: это описания ожиданий. Исполнитель — стенд S11 и интеграция S25; статусы `R-169…R-187` и экспериментальных требований остаются `planned`. Имена полей payload (`supersedes`, `claim_kind`, `notice_level`, `focus`, `layer`, `checked_on_copy`…) и логические пути состояния — предварительные договорённости (D-010). Критерий «функциональное требование имеет сценарий или тест» проверяется грубо, по словам в `check` (42 требования закрыты сценарием, 58 — только обещанием теста); смысловую достаточность проверок оценивает ревью. Профили временных персонажей (`persona`) не созданы и не проверяются (S11). Значения начальных настроек в сценариях (месяц/недели жизни, лимиты) предполагают отключённый лимит сеанса, кроме сценария о лимите (`scenario-format.md`, §6а).
