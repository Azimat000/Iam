# S29 — Итоговая приёмка и свидетельства

**Этап:** 5 (завершение) · **Зависит от:** S28 · **Требования:** семь критериев итоговой готовности

## Условие завершения и переход (D-053)

Все 7 критериев PLAN §5.4 выполнены одновременно; реестр не содержит planned/implemented и битых свидетельств. Отказ от необязательного требования допускается только по явному решению пользователя, без подмены семи критериев. G08: среднее ≥4/5 и ни одного балла ниже 3 по признаку; пилот принят; отчёт и руководство готовы.

**Подтверждение:** docs/FINAL_REPORT.md, финальный отчёт реестра, исходные оценки пользователя и расчёт, независимая проверка свидетельств.

**После приёмки:** Проект завершён только при всех условиях. При провале — конечный перечень невыполненного и решение о доработке; бесконечный сбор новых оценок запрещён.

**Предел повторов:** [общий протокол и специальные бюджеты](../COMPLETION.md). Контракт уточняет раздел «Проверки»; прежний ход работы и итоги ниже остаются историей, а не новым требованием повторять эксперименты.

## Простыми словами
Финальный экзамен. Проходим по семи критериям из плана: технические ограничения и восстановление; участие опыта в решениях; самостоятельные занятия с сохранёнными результатами; совместная работа памяти, эмоций, мотивации и самомодели; ваши оценки узнаваемости, естественности и самостоятельности (среднее ≥ 4 из 5, ни одной оценки ниже 3 по признаку); пилот без необъяснённой потери; конкретное свидетельство на каждое требование. Что не выполнено — остаётся видимым в реестре и не объявляется завершённым.

## Что делаем
- `reqs.py report --final`: каждое требование `verified` с работающей ссылкой на свидетельство либо `waived` с обоснованием, одобренным пользователем.
- До получения оценок фиксируется пакет из 3 полных диалогов начала/середины/конца пилота по датам: 3 признака × 3 диалога = 9 исходных баллов. Среднее ≥4/5, каждый балл ≥3. Правило повторной оценки и сохранения неуспешной — docs/COMPLETION.md; пустые оценки не заполняются автоматически.
- Итоговый отчёт `docs/FINAL_REPORT.md`: что готово, доказательства, известные ограничения, что вне объёма (соцсети, внешность, голос, медиа) и как ядро позволяет их подключить.
- Передаточная документация: структура, обслуживание, копии, дальнейшие шаги.

## Границы файлов
Можно: `docs/**`, `tools/reqs.py`, `requirements.toml`, малые исправления с тестами.
Нельзя: объявлять требование выполненным без свидетельства.

## Проверки
- `reqs.py report --final` без `planned`/`implemented` и без битых ссылок на свидетельства.
- Оценки пользователя занесены дословно; вывод по критерию 5 вычислен скриптом.
- Независимый ревьюер-подагент проверяет случайную выборку требований: свидетельство действительно подтверждает.
