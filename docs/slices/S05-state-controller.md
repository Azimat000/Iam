# S05 — Каркас: контроллер состояния и время жизни

**Этап:** 2 (Технический каркас) · **Зависит от:** S04 · **Требования:** StateController, версии состояния, идемпотентность, время жизни

## Простыми словами
«Привратник» личности. Любое изменение (от модели, Telegram, оператора) приходит как *предложение* с номером версии состояния. Привратник проверяет: не устарело ли (ответ модели, который опоздал, отбрасывается), не применялось ли уже (повтор не срабатывает дважды), допустимо ли — и только тогда записывает изменение и новое событие одной неделимой операцией. Кроме того, здесь «часы жизни»: пока программа выключена или на паузе, время личности стоит.

## Что делаем
- `iam.state.StateController.apply(proposal)`: проверка версии (устаревшее → отказ с записью), ключ идемпотентности (повтор → без эффекта), валидаторы переходов, транзакция «состояние + событие», результат применения.
- Конверты запрос/ответ с идентификаторами и версиями (по спецификации S02).
- `iam.clock.LifeClock`: жизненное время идёт только в активном сеансе; события паузы/возобновления; плановые моменты в жизненном времени.
- Воспроизведение: состояние, пересобранное из журнала, совпадает со снимком.

## Проверки
- Сценарии «повтор результата или старый ответ», «пауза и перезапуск» проходят автоматически.
- Фазз-тест: случайные последовательности предложений (дубли, устаревшие, параллельные) → инварианты (версия монотонна, нет двойного применения, replay == снимок).
- Жизненное время не растёт при остановленном сеансе (тест с подменой календарных часов).
