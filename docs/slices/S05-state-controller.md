# S05 — Каркас: контроллер состояния и время жизни

**Этап:** 2 (Технический каркас) · **Зависит от:** S04 · **Требования:** StateController, версии состояния, идемпотентность, время жизни

## Условие завершения и переход (D-053)

Устаревшие версии/эпохи и повторы не меняют состояние; случайные последовательности сохраняют replay == снимок; пауза и остановка не увеличивают жизненное время.

**Подтверждение:** Тесты контроллера, версий, повторов и часов с сохранённым результатом прогона.

**После приёмки:** S06 и затем независимая от него ветвь S07; не добавлять психологические механизмы.

**Предел повторов:** [общий протокол и специальные бюджеты](../COMPLETION.md). Контракт уточняет раздел «Проверки»; прежний ход работы и итоги ниже остаются историей, а не новым требованием повторять эксперименты.

## Простыми словами
«Привратник» личности. Любое изменение (от модели, Telegram, оператора) приходит как *предложение* с номером версии состояния. Привратник проверяет: не устарело ли (ответ модели, который опоздал, отбрасывается), не применялось ли уже (повтор не срабатывает дважды), допустимо ли — и только тогда записывает изменение и новое событие одной неделимой операцией. Кроме того, здесь «часы жизни»: пока программа выключена или на паузе, время личности стоит.

## Что делаем
- `iam.state.StateController.apply(proposal)`: проверка версии (устаревшее → отказ с записью), ключ идемпотентности (повтор → без эффекта), валидаторы переходов, транзакция «состояние + событие», результат применения.
- Конверты запрос/ответ с идентификаторами и версиями (по спецификации S02).
- `iam.clock.LifeClock`: жизненное время идёт только в активном сеансе; события паузы/возобновления; плановые моменты в жизненном времени.
- Воспроизведение: состояние, пересобранное из журнала, совпадает со снимком.

## Проверки
- Сценарии «повтор результата или старый ответ», «пауза и перезапуск» проходят автоматически.
- Фазз-тест: случайные последовательности предложений (дубли, устаревшие, параллельные) → инварианты (версия монотонна, нет двойного применения, replay == снимок).
- Жизненное время не растёт при остановленном сеансе (тест с подменой календарных часов).

## Итог
**Сделано.** Пакеты `iam.clock` и `iam.state` (решение D-012).
- `iam.clock`: `LifeClock` — время жизни по монотонным часам, идёт только в сеансе, замораживается ровно на записанном в событие паузы значении, не убывает; восстановление после аварии (максимум из heartbeat и последнего события); `time_scale` только экспериментальным личностям. Плановые моменты `life`/`calendar` (чистые функции).
- `iam.state.StateController`: `apply(Proposal)` — дубль по ключу (повтор — `duplicate`, другое содержимое — `conflict` + `system.error`), версия `(epoch, state_version)` (иначе `stale` + `proposal.stale`), права исполнителя, допустимость при сеансе, защищённые поля и зарезервированные носители, основания, операции `set/add/remove/transition`, конечные автоматы (намерения, сеанс; статус не обойти записью напрямую; `done` — только с подтверждением), записи памяти `add/set`, пользовательские валидаторы; запись «события перехода + память + снимок» одной транзакцией; отказы пишутся в журнал. `receive_response`/`record_request` — конверты запрос/ответ: эхо, устаревание (версия, сеанс, срок), дубль, `tool_use`, проверка каждого предложения, принятые `state_change` — один переход. Сеанс (`start/pause/resume/stop`), перезапуск после аварии (`session.paused` причина `crash`), моменты, `tick`/heartbeat, вмешательства оператора (`intervene`, `technical_fix`), `create_persona`.
- `iam.state.replay/verify`: состояние, пересобранное из журнала, сверяется с записанными изменениями и со снимком каждой версии, с записями памяти и неубыванием времени жизни.

**Как проверено.** 407 тестов зелёные; `tools/covcheck.py`: все 27 модулей выше порогов, критичные `iam.state` и `iam.clock` — 100 % строк и ветвей (`docs/evidence/S05-state.md`). Проверки среза: «повтор результата / старый ответ» (`test_response.py`, `test_controller.py`), «пауза и перезапуск» (`test_session.py`: сутки календарной паузы не входят в жизнь, авария → пауза `crash`, жизнь от максимума heartbeat и события); фазз-тест (25 серий × 300 случайных шагов: дубли, устаревшие, параллельные, конфликтные ключи, ответы модели, паузы — версия монотонна и растёт ровно на переход, ни один переход не применён дважды, состояние == воспроизведение == снимок); `kill -9` контроллера 25 раз — состояние согласовано; второй процесс-писатель отклонён; статический тест «методы записи хранилища вызывают только storage/state/clock» (R-105). Мутации (отключение проверки версии, дедупликации, защиты времени, заморозки часов) тестами ловятся. Независимое ревью подагентом: 1 блокирующая (обход автомата записью статуса напрямую), 5 важных, несколько мелких — исправлены с тестами (D-012, «Уточнения»). Статусы: R-024, R-025, R-034, R-105, R-107 — `verified`; R-013, R-108, R-182, R-183 — `implemented` (их проверка в реестре — прогон сценариев каталога, исполнитель появится в S11/S25).

**Не сделано / ограничения.** Виды предложений `action`, `message`, `memory_write`, `intention`, `creator_request`, `no_action`, `attend` пока отклоняются (`kind_not_supported`) — их разбирает цикл (S07) и модули S18+. Встроенных диапазонов полей групп нет (задают владельцы групп через `add_validator`, S20–S24). «Поздние результаты» действий в паузе (`payload.late`) не реализованы: противоречат каталогу событий (`changes_state`), решает S07/S12. Операции памяти `remove/transition`, слой `archive` — S18–S19. Воспроизведение через смену эпохи — S06 (сейчас `ReplayError`). Подтверждение для `done` не привязано к конкретному намерению (S22). Контроллер однопоточен (соединение SQLite привязано к потоку).

**Унаследовать следующим срезам.** S06: резервная копия в хук `before` мигратора; восстановление = эпоха +1, событие `system.restored` и воспроизведение через смену эпохи (`replay` ждёт этого). S07: приём входящих — `input.arrived` + строка `inbox` в одной транзакции (через контроллер: вне `storage/state/clock` писать в `Store` нельзя, тест R-105), обработчики остальных видов предложений, лимит `max_rerequest`, бюджет сеанса (30 минут / 10 обращений), запись `system.limit_reached` перед `session.paused`, поздние результаты действий. S10: панель открывает базу `readonly=True`, `StateController` в этом режиме только читает. Перед замером в новой сессии: `pip install 'coverage==7.10.6'`.
