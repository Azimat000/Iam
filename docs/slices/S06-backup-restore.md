# S06 — Каркас: копии, восстановление, экспорт

**Этап:** 2 (Технический каркас) · **Зависит от:** S05 · **Требования:** резервные копии, восстановление, экспорт без секретов, нехватка места

## Условие завершения и переход (D-053)

Хранятся три последних согласованных снимка; миграция без копии запрещена; восстановление на отдельной базе воспроизводит состояние и отмечает вмешательство; экспорт без контрольных секретов; нехватка места безопасно останавливает запись.

**Подтверждение:** Позитивные и негативные тесты копий/экспорта/восстановления и отчёт.

**После приёмки:** S07 либо S10 после его остальных зависимостей. Внешний экземпляр копии проверяется в S27.

**Предел повторов:** [общий протокол и специальные бюджеты](../COMPLETION.md). Контракт уточняет раздел «Проверки»; прежний ход работы и итоги ниже остаются историей, а не новым требованием повторять эксперименты.

## Простыми словами
Страховка. Автоматические снимки базы (хранятся три последних), обязательная копия перед любым обновлением формата базы, ручной экспорт «личности» без паролей и токенов, и восстановление — сначала на отдельной копии, с проверкой, что всё согласовано. Если места на диске мало, программа останавливается заранее, а не ломает данные посреди записи.

## Что делаем
- Снимки через онлайн-API SQLite, ротация до 3, проверка целостности каждого снимка.
- Хук «копия перед миграцией»: миграция без свежей копии отклоняется.
- Экспорт: пакет без секретов (проверка сканером по шаблонам и «канареечным» секретам).
- Восстановление: в отдельный каталог → проверка целостности и воспроизведения → событие «восстановление выполнено» в журнале восстановленной личности.
- Защита от нехватки места: проверка запаса до записи, чистая остановка сеанса.
- CLI: `iam backup|export|restore|verify`.

## Границы файлов
Можно: `src/iam/backup/**`, `src/iam/cli.py` (только команды копий), `tests/backup/**`, `requirements.toml`.
Нельзя: менять логику StateController.

## Проверки
- Сценарий «восстановление копии» проходит: состояние согласовано, восстановление отмечено.
- Канареечный секрет не попадает в экспорт (тест).
- Симуляция нехватки места: сеанс останавливается, база цела.
- Ротация оставляет ровно 3 снимка; повреждённый снимок обнаруживается.

## Итог
**Сделано.** Пакет `iam.backup` и CLI `iam backup|export|restore|verify` (решение D-013).
- Снимки: онлайн-копия SQLite отдельным соединением «только чтение», проверка (sha256, `integrity_check`, полное воспроизведение журнала), манифест, ротация до 3 (только целые копии; повреждённая называется, а не удаляется молча; только что сделанный снимок не удаляется никогда).
- Копия перед миграцией: `migration_hook`/`open_for_write` — свежая проверенная копия в `pre-migration/`; не удалась — миграция не начинается.
- Восстановление: только в отдельный каталог, проверка на отдельной копии до и после отметки, эпоха +1, `operator.intervention(restore_backup)` + `system.restored` (с `checked_on_copy`, разрывом `lost_seq_*`) + снимок новой эпохи, атомарное появление базы, живая база не трогается. `iam.state.restore.mark_restored`; воспроизведение (`iam.state.replay`) понимает границу эпох.
- Экспорт: zip с манифестом, редактирование секретов + перепроверка готового пакета (найден секрет — пакета нет); сканер секретов (шаблоны, «канарейки», секреты окружения).
- Нехватка места: `SpaceGuard`, `guarded_call`, `stop_on_low_space` (запись `system.error`, остановка сеанса; настоящий SQLITE_FULL откатывает запись целиком).

**Как проверено.** 512 тестов зелёные (101+ новых в `tests/backup`); `tools/covcheck.py`: 36 модулей, ниже порога нет, все модули среза (`iam.backup.*`, `iam.state.restore`, `cli.py`) — 100 % строк и ветвей (`docs/evidence/S06-backup.md`). Проверки среза: сценарий «восстановление копии» (`test_restore.py`: состояние из копии, эпоха 1→2, `system.restored`, опыта после копии нет, ответ модели прежней эпохи — `stale`); канареечный секрет не попадает в экспорт (`test_export.py`, в том числе в сыром zip; сломанный редактор → `SecretFound`, файла нет); симуляция нехватки места (проверка запаса и настоящий SQLITE_FULL: сеанс остановлен, `verify` и `integrity_check` чисты); ротация ровно 3, повреждённая копия обнаружена. Независимое ревью подагентом: блокирующих нет, 2 важных (путь с `#`/`?`/`%` — исправлено в т. ч. в `storage/db.py`; токен после `bot` — исправлено) и несколько мелких — исправлены с тестами, остаток записан в D-013. Статусы: R-200…R-204 — `verified`; R-187, R-205, R-219 — `implemented` (сценарий каталога на ядре — S25, хаос-набор — S10, токен в логах — S09, авторизация исполнителя — S08).

**Не сделано / ограничения.** `guarded_call` не встроен в цикл сеанса (цикл — S07, хаос-проверки — S10). Сканер секретов — страховка по шаблонам: короткие/нераспознаваемые секреты, не заведённые как «канарейки», не найдёт. Копия без манифеста (обрыв между переименованием и манифестом) числится повреждённой до ручной уборки. Голый `Store.open` без хука мигрирует без копии (обязателен `open_for_write`; сторожевой тест — S07). Автоматического расписания снимков и замены живой базы восстановленной нет (осознанно — шаг оператора). Копии локальны: от потери самого компьютера нужна копия на другом устройстве (PLAN §5). `db.connect` не закрывает соединение при ошибке на не-базе (мелочь S04, `ResourceWarning`).

**Унаследовать следующим срезам.** S07: вызывать `guarded_call` вокруг записей сеанса; перед миграциями открывать личность через `iam.backup.open_for_write`; при запуске сеанса можно снимать копию (`create_backup(..., controller=c)`); после восстановления первый запуск контроллера ставит паузу `crash`, если копия снята во время идущего сеанса. S10: хаос-набор с нехваткой места поверх `SpaceGuard`/`guarded_call`. S25: сценарий `restore_backup` считает эпоху из `(epoch)` событий/снимков (поля `world_time.epoch` в состоянии нет); утверждение `checked_on_copy` берётся из `system.restored.payload`. Перед замером в новой сессии: `pip install 'coverage==7.10.6'`.
