# S08 — Каркас: изолированный исполнитель Codex

**Этап:** 2 (Технический каркас) · **Зависит от:** S07 · **Требования:** изоляция, структурированный ответ, ошибки авторизации/лимита, ограничения сеансов

## Простыми словами
Безопасная «комната» для внешней модели. Модель запускается в отдельном контейнере Docker, который не видит ни ваших папок, ни базы личности, ни токена Telegram, ни Docker; выход в сеть — только через посредника с белым списком адресов; вопрос подаётся через вход, ответ забирается с выхода. Если модель попыталась воспользоваться инструментом — ответ считается непригодным. Здесь, в облаке, настоящий Docker и Codex недоступны, поэтому я пишу всё и проверяю на «подделке Codex»; настоящая проверка — на вашем Mac (барьер G01) по готовому скрипту.

## Что делаем
- Перед написанием флагов — сверить актуальную документацию Codex CLI (неинтерактивный режим, структурированный вывод, авторизация); ничего не «вспоминать по памяти».
- `docker/`: Dockerfile (linux/arm64, не root), конфигурация посредника (белый список адресов), описание запуска (read-only, `--cap-drop ALL`, лимиты CPU/памяти/процессов, без монтирования домашних папок и docker.sock, без токенов в окружении).
- `iam.providers.CodexProvider` — адаптер `CognitiveProvider`: контекст на stdin → `codex exec` → JSON с stdout; классификатор ошибок (авторизация, лимит, формат, таймаут, попытка использовать инструменты); одна повторная попытка при неверном формате; маршрутизация «дешёвая/сильная модель» по классу задачи.
- Бюджет сеанса: 30 минут или 10 обращений; при исчерпании/ошибке авторизации/повторном сбое — техническая пауза с сохранением состояния.
- `FakeCodex` для тестов. Опционально оценить `ClaudeCliProvider` (`claude -p` доступен в этой среде) как альтернативный адаптер — только если это согласуется с допущением A1.
- `scripts/codex/verify_isolation.sh` и шаблон отчёта `docs/evidence/codex-isolation.md` для запуска на Mac.

## Границы файлов
Можно: `docker/**`, `scripts/codex/**`, `src/iam/providers/**`, `tests/providers/**`, `docs/evidence/**`, `requirements.toml`.
Нельзя: хранилище, контроллер состояния (только использовать).

## Проверки
- Тест сборщика команды `docker run`: каждый флаг изоляции присутствует, запрещённые монтирования отсутствуют (набор негативных тестов).
- Классификатор ошибок: таблица входов → ожидаемые классы; бюджеты и техническая пауза; сценарий «ошибка авторизации или лимит Plus».
- Контрактные тесты адаптера на FakeCodex (валидный, мусорный, с попыткой инструмента, зависший).
- `bash -n` скрипта проверки; шаблон отчёта заполняется машинно.
- Условие перехода плана §3: пока G01 не закрыт, S26 и S27 не стартуют (проверяет `memory.py`).
- Сценарий «смена модели» (подмена провайдера) сохраняет состояние.
