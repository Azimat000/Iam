# S08 — Каркас: изолированный исполнитель Claude Code (подписка)

> **Решение D-015 (2026-10-16):** рабочий интеллект — модели подписки Claude Code, не Codex. Ниже «Codex» из плана читается как «Claude Code (`claude -p`)»; барьер G01 заменён на G11.

**Этап:** 2 (Технический каркас) · **Зависит от:** S07 · **Требования:** изоляция, структурированный ответ, ошибки авторизации/лимита, ограничения сеансов

## Простыми словами
Безопасная «комната» для внешней модели (Claude Code по вашей подписке). Модель запускается в отдельном контейнере Docker, который не видит ни ваших папок, ни базы личности, ни токена Telegram, ни Docker; выход в сеть — только через посредника с белым списком адресов; вопрос подаётся через вход, ответ забирается с выхода. Если модель попыталась воспользоваться инструментом — ответ считается непригодным. Здесь, в облаке, настоящий Docker и вход в подписку недоступны, поэтому я пишу всё и проверяю на «подделке Claude»; настоящая проверка — на вашем Mac (барьер G11) по готовому скрипту.

## Что делаем
- Перед написанием флагов — сверить актуальную документацию Claude Code CLI (`claude -p`, формат вывода, запрет инструментов, сессии, авторизация подписки в контейнере); ничего не «вспоминать по памяти».
- `docker/`: Dockerfile (linux/arm64, не root), конфигурация посредника (белый список адресов), описание запуска (read-only, `--cap-drop ALL`, лимиты CPU/памяти/процессов, без монтирования домашних папок и docker.sock, без токенов в окружении).
- `iam.providers.ClaudeCodeProvider` — адаптер `CognitiveProvider`: контекст на stdin → `claude -p` → JSON с stdout; классификатор ошибок (авторизация, лимит, формат, таймаут, попытка использовать инструменты); одна повторная попытка при неверном формате; маршрутизация «дешёвая/сильная модель» по классу задачи.
- Бюджет сеанса: 30 минут или 10 обращений; при исчерпании/ошибке авторизации/повторном сбое — техническая пауза с сохранением состояния.
- `FakeClaude` для тестов (подделка исполнителя). Адаптер строится под `claude -p` (доступен и в этой среде для проверки флагов, но личность в облаке не запускается).
- `scripts/claude/verify_isolation.sh` и шаблон отчёта `docs/evidence/claude-isolation.md` для запуска на Mac.

## Границы файлов
Можно: `docker/**`, `scripts/claude/**`, `src/iam/providers/**`, `tests/providers/**`, `docs/evidence/**`, `requirements.toml`.
Нельзя: хранилище, контроллер состояния (только использовать).

## Проверки
- Тест сборщика команды `docker run`: каждый флаг изоляции присутствует, запрещённые монтирования отсутствуют (набор негативных тестов).
- Классификатор ошибок: таблица входов → ожидаемые классы; бюджеты и техническая пауза; сценарий «ошибка авторизации или лимит подписки».
- Контрактные тесты адаптера на FakeClaude (валидный, мусорный, с попыткой инструмента, зависший).
- `bash -n` скрипта проверки; шаблон отчёта заполняется машинно.
- Условие перехода плана §3: пока G01 не закрыт, S26 и S27 не стартуют (проверяет `memory.py`).
- Сценарий «смена модели» (подмена провайдера) сохраняет состояние.
