## Простыми словами
Безопасная «комната» для внешней модели (Claude Code по вашей подписке). Модель запускается в отдельном контейнере Docker, который не видит ни ваших папок, ни базы личности, ни токена Telegram, ни Docker; выход в сеть — только через посредника с белым списком адресов; вопрос подаётся через вход, ответ забирается с выхода. Если модель попыталась воспользоваться инструментом — ответ считается непригодным. Здесь, в облаке, настоящий Docker и вход в подписку недоступны, поэтому я пишу всё и проверяю на «подделке Claude»; настоящая проверка — на вашем Mac (барьер G11) по готовому скрипту.

## Что делаем
- Перед написанием флагов — сверить актуальную документацию Claude Code CLI (`claude -p`, формат вывода, запрет инструментов, сессии, авторизация подписки в контейнере); ничего не «вспоминать по памяти».
- `docker/`: Dockerfile (linux/arm64, не root), конфигурация посредника (белый список адресов), описание запуска (read-only, `--cap-drop ALL`, лимиты CPU/памяти/процессов, без монтирования домашних папок и docker.sock, без токенов в окружении).
- `iam.providers.ClaudeCodeProvider` — адаптер `CognitiveProvider`: контекст на stdin → `claude -p` → JSON с stdout; классификатор ошибок (авторизация, лимит, формат, таймаут, попытка использовать инструменты); одна повторная попытка при неверном формате; маршрутизация «дешёвая/сильная модель» по классу задачи.
- Бюджет сеанса: 30 минут или 10 обращений; при исчерпании/ошибке авторизации/повторном сбое — техническая пауза с сохранением состояния.
- `FakeClaude` для тестов (подделка исполнителя). Адаптер строится под `claude -p` (доступен и в этой среде для проверки флагов, но личность в облаке не запускается).
- `scripts/claude/verify_isolation.sh` и шаблон отчёта `docs/evidence/claude-isolation.md` для запуска на Mac.

## Итог
**Сделано** (решения D-015, D-016). Рабочий интеллект личности — модели подписки Claude Code, не Codex.
- `iam.providers.ClaudeCodeProvider` — адаптер `CognitiveProvider`: контекст в stdin, ответ из stdout, в модель уходят только необходимые фрагменты; идентификаторы предложений, эхо запроса и `tool_use_detected` назначает адаптер; одна повторная попытка по формату (R-194); маршрутизация «дешёвая `sonnet` / сильная `opus`» по классу задачи (R-192, R-193).
- `classify` — классификатор результата запуска (ok, auth, limit, unavailable, format, timeout, tool_use, exec, unknown); опирается на реально снятый образец ошибки входа (код возврата 0, `is_error`, `api_error_status`), а не на код процесса.
- `docker_run` — сборщик `docker run`: read-only, `--cap-drop ALL`, no-new-privileges, не root, лимиты, linux/arm64, внутренняя сеть, `--pull never`, ни одного монтирования, токен файлом, закрытый перечень окружения; небезопасную конфигурацию собрать нельзя.
- `SessionBudget`/`BudgetedRunner`/`PausingProvider` — 30 минут или 10 обращений, техническая пауза с причиной (`session_limit`, `auth_lost`, `repeated_failure`), запись `system.limit_reached` перед `session.paused`, бюджет восстанавливается из журнала после перезапуска (R-191; сценарий «ошибка авторизации или лимит»).
- `FakeClaude`, `docker/` (Dockerfile, squid с белым списком, compose с внутренней сетью), `scripts/claude/verify_isolation.sh` + `render_report.py` + шаблон отчёта.

**Как проверено.** 709 тестов зелёные (+100 новых в `tests/providers`), `covcheck`: `iam.providers` 100 % строк и ветвей (критичный модуль), все пороги (`docs/evidence/S08-claude-executor.md`). Негативные тесты сборщика (каждый флаг на месте, запрещённого нет, небезопасная конфигурация не собирается; клиент docker принимает все наши флаги); таблица классификатора; контрактные тесты адаптера на FakeClaude (валидный, мусор, попытка инструмента, зависание, ошибки по классам); настоящий запуск процесса через stdin/stdout с таймаутом; цикл S07 поверх провайдера; «смена модели». **Скрипт проверки на Mac прогнан на подделке docker:** идеальный контейнер даёт «ПРОЙДЕНА», каждая из 16 искусственных дыр ловится своей проверкой, «мёртвый» docker не даёт ни одной ложной PASS, токен в вывод и отчёт не попадает; на этом прогоне найдены и исправлены настоящие дефекты скрипта. Независимая проверка подагентом: 2 блокирующие и 12 важных/мелких замечаний исправлены (D-016, «Уточнения»); 33 из его 38 мутаций сразу были пойманы, для 5 выживших добавлены тесты. Статусы: R-116, R-191–R-194 — `verified`; R-015, R-109–R-115, R-118, R-119, R-149 — `implemented` (живая проверка на Mac, G11); R-208 — `planned` (нужен закрытый G09).

**Не сделано / не проверено.** Реальные Docker, вход по подписке, форма *успешного* ответа, ошибка лимита подписки и признаки попытки инструмента при `--tools ""` — только на Mac (барьер **G11**, не даёт стартовать S26–S27). Политики данных подписки и допустимость автоматического запуска — G09 (за вами). Образ-основа и squid закреплены тегом, не дайджестом; имя npm-пакета и версию подтвердит сборка. `edit_config` (запись замены поставщика) — S10. Адаптер не фильтрует слои контекста сам; DNS-канал не проверяется; `max_output_tokens` — просьба, не ограничение.

S10: панель показывает бюджет, паузу и причину (`world.limits.*`, `session.paused`), `edit_config`, `PausingProvider`+`BudgetedRunner` оборачивают провайдера при сборке приложения (`SessionBudget.from_journal` при старте), встраивание `guarded_call` (S06).
