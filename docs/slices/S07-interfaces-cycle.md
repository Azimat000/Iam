# S07 — Каркас: интерфейсы ядра и цикл на заглушках

**Этап:** 2 (Технический каркас) · **Зависит от:** S05 · **Требования:** границы модель/ядро, шесть интерфейсов, общий цикл

## Простыми словами
Строим «скелет мышления»: цикл *событие → внимание → память → оценка → предложение → проверка ядром → действие → подтверждённый результат → обновление памяти* и шесть «розеток» (интерфейсов), в которые потом вставятся настоящие части. Пока в розетках простые заглушки, мыслей нет — но весь путь проходит, каждый шаг пишется в журнал, а сбой действия не выдаётся за успех. Благодаря «розетке» CognitiveProvider интеллект можно заменить (Codex, Claude, формальные правила) без переделки остального.

## Что делаем
- `iam.interfaces`: Protocol-ы `CognitiveProvider`, `Memory`, `World`, `Capabilities`, `CreatorBridge`, `StateController`.
- `iam.stubs`: ScriptedProvider (заранее записанные ответы), простейшие Memory/World/Capabilities/CreatorBridge в памяти.
- `iam.cycle`: исполнитель цикла с событиями шагов, предельным числом решений, обработкой ошибок на каждом шаге.
- Валидатор структурированного предложения: любые признаки использования инструментов/выполнения действий внутри ответа модели → предложение отклонено.
- Правило: предложение ≠ воспоминание о действии; воспоминание создаётся только после подтверждённого результата.

## Границы файлов
Можно: `src/iam/interfaces/**`, `src/iam/stubs/**`, `src/iam/cycle/**`, `tests/cycle/**`, `requirements.toml`.
Нельзя: реальные провайдеры, Telegram, панель.

## Проверки
- Полный проход цикла на заглушках оставляет в журнале все стадии с идентификаторами и версиями.
- Сценарии «сбой во время действия» и «нет нужного инструмента» (на заглушках) проходят: нет выдуманного успеха.
- Просроченный ответ провайдера не применяется (через контроллер из S05).
- Подмена заглушки другой реализацией интерфейса не требует правок цикла (тест-двойник).
