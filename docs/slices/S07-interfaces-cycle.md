# S07 — Каркас: интерфейсы ядра и цикл на заглушках

**Этап:** 2 (Технический каркас) · **Зависит от:** S05 · **Требования:** границы модель/ядро, шесть интерфейсов, общий цикл

## Простыми словами
Строим «скелет мышления»: цикл *событие → внимание → память → оценка → предложение → проверка ядром → действие → подтверждённый результат → обновление памяти* и шесть «розеток» (интерфейсов), в которые потом вставятся настоящие части. Пока в розетках простые заглушки, мыслей нет — но весь путь проходит, каждый шаг пишется в журнал, а сбой действия не выдаётся за успех. Благодаря «розетке» CognitiveProvider интеллект можно заменить (Codex, Claude, формальные правила) без переделки остального.

## Что делаем
- `iam.interfaces`: Protocol-ы `CognitiveProvider`, `Memory`, `World`, `Capabilities`, `CreatorBridge`, `StateController`.
- `iam.stubs`: ScriptedProvider (заранее записанные ответы), простейшие Memory/World/Capabilities/CreatorBridge в памяти.
- `iam.cycle`: исполнитель цикла с событиями шагов, предельным числом решений, обработкой ошибок на каждом шаге.
- Валидатор структурированного предложения: любые признаки использования инструментов/выполнения действий внутри ответа модели → предложение отклонено.
- Правило: предложение ≠ воспоминание о действии; воспоминание создаётся только после подтверждённого результата.

## Границы файлов
Можно: `src/iam/interfaces/**`, `src/iam/stubs/**`, `src/iam/cycle/**`, `tests/cycle/**`, `requirements.toml`.
Нельзя: реальные провайдеры, Telegram, панель.

## Проверки
- Полный проход цикла на заглушках оставляет в журнале все стадии с идентификаторами и версиями.
- Сценарии «сбой во время действия» и «нет нужного инструмента» (на заглушках) проходят: нет выдуманного успеха.
- Просроченный ответ провайдера не применяется (через контроллер из S05).
- Подмена заглушки другой реализацией интерфейса не требует правок цикла (тест-двойник).

## Итог
**Сделано.** Пакеты `iam.interfaces`, `iam.stubs`, `iam.cycle` и небольшое расширение `iam.state` (решение D-014).
- Шесть «розеток» (`typing.Protocol`): `CognitiveProvider`, `Memory`, `World`, `Capabilities`, `CreatorBridge`, `StateController`; заглушки на все (`ScriptedProvider`, `StubWorld` с поведениями «подтвердить / не вышло / неизвестно / обрыв», `StubMemory`/`StoreMemory`, `StubCapabilities`, `StubCreatorBridge`).
- Цикл `Cycle.run(событие)`: внимание → память → запрос (`proposal.requested`) → ответ (`proposal.received`) → проверка привратником → попытка → исход от мира → воспоминание; каждая стадия — события журнала с эпохой/версией и запись `StageRecord`. `Runner.run_pending`: циклы только по событиям-поводам, нет повода — нет обращения к провайдеру; предел решений, раунды, пауза.
- Валидатор предложений: признаки инструментов/«выполнено» → весь ответ непригоден; у каждого вида только свои поля тела.
- Привратник: `register_kind` (разборщики видов `action/message/creator_request/no_action/attend` превращают предложение в операции «принято»), автомат исхода действия `accepted → attempted → confirmed | failed | unknown_outcome` с правами по типам событий и событием-носителем; пути `world.actions`/`world.creator_requests` модель не правит.
- Воспоминание о действии — отдельным переходом и только после подтверждения; сбой/обрыв/потерянный ответ → `unknown_outcome`/`message.out_unknown`, не успех; зависшая попытка после рестарта закрывается так же.

**Как проверено.** 609 тестов зелёные (97 новых в `tests/cycle`), `tools/covcheck.py`: все 51 модуль выше порогов, `iam.cycle`, `iam.state` — 100 % строк и ветвей (`docs/evidence/S07-cycle.md`). Проверки среза: полный проход с трассой стадий по порядку (`test_cycle.py`); «сбой во время действия» (обрыв мира, смерть процесса + рестарт, потерянное подтверждение, мусор вместо ответа мира) и «нет нужного инструмента» (`test_safety.py`); устаревший ответ не применяется, перезапрос ≤ `max_rerequest`, одна попытка исправить формат; подмена каждой заглушки и привратника тест-двойником без правок цикла, цикл не импортирует заглушки/хранилище (`test_interfaces.py`); 40 случайных прогонов с инвариантами «подтверждено ⇒ была попытка и это событие мира», «воспоминание ⇔ подтверждение», «один исход на действие», воспроизведение журнала сходится (`test_fuzz.py`). Мутации (отключение экрана инструментов, памяти «только после подтверждения», ключа идемпотентности цикла, фильтра доступных возможностей) тестами ловятся. Независимая проверка подагентом: 1 блокирующая (цепочка `state_change` давала `confirmed` без мира) и 6 важных — исправлены с тестами (D-014, «Уточнения»); он же прогнал 29 собственных мутаций — все пойманы. Статусы: R-036, R-103, R-104, R-106 — `verified`; R-117, R-184, R-199, R-222 — `implemented` (прогон сценариев каталога на ядре — S25; классификатор результата исполнителя для R-117 — S08).

**Не сделано / ограничения.** Стадии восприятия `input.noticed`/`input.read` и настоящий фильтр непрочитанного — S20 (пока содержимое входящего в запросы не попадает вообще); приём Telegram и `inbox` одной транзакцией — S09; виды `memory_write`, `intention` — `kind_not_supported` до S18/S22; бюджет сеанса (30 мин / 10 обращений), `system.limit_reached`, «поздние результаты» — S10/S12; повторная отправка потерянного сообщения не делается совсем; действие, принятое, но не начатое из-за обрыва, остаётся без исхода (ничего не выполнялось); очередь повторов раннера живёт в памяти процесса; реестр возможностей и права — заглушка (S23). Валидатор не читает смысл текста (фраза «я построила график» в `rationale` ловится только отсутствием возможности).

**Унаследовать следующим срезам.** S08: настоящий `CognitiveProvider` (Codex-исполнитель) отдаёт ответ по `response.schema.json`, классификатор результата выставляет `tool_use_detected`; цикл сам доверяет только структуре.
