# S09 — Каркас: Telegram-приёмник и отправка

**Этап:** 2 (Технический каркас) · **Зависит от:** S07 · **Требования:** приёмник без вызова моделей, надёжный приём, дедупликация, неопределённая отправка

## Простыми словами
«Почтовый ящик» личности. Маленькая программа принимает ваши сообщения из Telegram даже когда личность «спит» и надёжно складывает их в ящик, не обращаясь к моделям. Сообщение считается принятым Telegram'ом только после того, как мы его сохранили (иначе при сбое оно потеряется), а повторная доставка одного и того же сообщения не создаёт «второго опыта». Личность видит лишь «пришло N сообщений»; содержание станет частью её опыта только когда она сама решит прочитать. На отправке: если неизвестно, дошло ли сообщение, мы это честно отмечаем и не пересылаем бесконечно.

## Что делаем
- `iam.telegram.Receiver`: long-poll `getUpdates`, сохранение в inbox до продвижения offset, дедупликация по `update_id`.
- Белый список числовых id и только личные диалоги; обычное сообщение — социальное событие, не команда; права меняются только через панель.
- Уровни уведомления: счётчик/факт нового сообщения; содержимое скрыто до события «прочитано».
- `iam.telegram.Sender` + outbox: состояния pending / sent / uncertain / failed, предел попыток.
- Поддельный сервер Telegram на `http.server` для тестов; токен только из окружения.
- `scripts/telegram/` — инструкция и проверка настоящего бота.

## Проверки
- Сбой между сохранением и подтверждением → потерь и дублей опыта нет (тест с обрывом).
- Сценарии «непрочитанное сообщение», «попытка получить права сообщением» проходят на заглушках.
- Чужой id и групповой чат отбрасываются; токен не попадает в логи/экспорт (канареечный тест).
- Потерянное подтверждение отправки → `uncertain`, повтор ограничен.
- Ограничение Telegram Bot API: при выключенном Mac больше суток входящие могут быть потеряны — записать в руководство оператора (docs/RUNBOOK.md в S27) и показать в панели предупреждением о давности последнего опроса.

## Итог
Реализованы Client, Receiver, Sender и CreatorBridge на стандартной библиотеке; запросы проходят настоящий HTTP к поддельному серверу. Приёмник принимает сообщения в stopped/paused без вызова модели; inbox, событие и offset фиксируются атомарно. Числовой белый список и private-чаты проверяются локально; дубли не создают второй опыт. N1/N2 скрывают текст, read_content требует input.read, сообщение с просьбой выдать права остаётся обычным входящим.

Отправка: одна постоянная попытка на action_id до сети; pending/requested, sent, uncertain/unknown, failed. Потеря подтверждения и авария не вызывают автоматической пересылки и не создают воспоминание об успехе. По умолчанию один явный повтор новым принятым действием с решением оператора; счётчик и связь сохраняются, цепочки повторов запрещены. Событие исхода и память пишет существующий Cycle; result_seq транспортного outbox остаётся NULL (D-017). Telegram-ошибка при опросе видима в журнале, но не блокирует внутренние дела.

Границы расширены по D-017: добавлен только src/iam/state/telegram.py — транспортная точка записи ядра, чтобы сохранить запрет прямых SQL/записей Store из iam.telegram. Существующие StateController, Cycle, Store и тест архитектурных границ не менялись. pyproject.toml включает Telegram в критичные модули; добавлены свидетельство, реестр и обязательная память проекта.
